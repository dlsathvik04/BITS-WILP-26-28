## 3. Key Concepts & Formal Definitions

| Concept / Term | Formal Definition & Operational Meaning | Contextual Constraints / Properties |
| :--- | :--- | :--- |
| **ARM** | Advanced RISC Machine; utilizes a Reduced Instruction Set Code where all instructions have a fixed execution time (1 machine cycle) and fixed storage length (4 bytes). | Instructions total fewer than 50, featuring low decoder complexity and abundant bit-manipulation capabilities. |
| **Machine Cycle** | The fundamental execution timeframe for a single instruction, which consists of multiple clock cycles. | In this specific architecture, 1 Machine Cycle = 20 Clock Cycles. |
| **Vectored Interrupt** | An interrupt where the address of the Interrupt Service Routine (ISR) is predefined and rigidly fixed in a vector table. | Managed by a Vector Interrupt Controller (VIC) or Nested Vector Interrupt Controller (NVIC). |
| **Link Register (LR)** | A dedicated register (R14) that stores the return address of an instruction when switching from one process or function to another. | Vital for context switching and returning from preempted processes. |
| **Thumb Mode** | An operational state where the processor executes 16-bit instructions instead of the standard 32-bit ARM instructions. | Though execution is 16-bit, the memory consumption footprint remains constant. |

## 4. Detailed Structured Technical Lecture Notes

### I. ARM Architecture and Memory Management

#### Overview & Theoretical Foundation
The ARM (Advanced RISC Machine) architecture operates on a highly predictable execution model utilizing a fixed-length instruction framework. Unlike complex instruction systems, ARM relies on tightly coupled memory systems to facilitate high-speed data access. True multiprocessing at the hardware level requires a multi-core architecture; however, ARM achieves apparent multiprocessing via rapid context switching managed tightly by memory control units. 

#### Mechanics & Operational Invariants
1. **Memory Management Unit (MMU):** Handles the allocation, deallocation, and physical data movement between flash memory and SRAM to reduce latency.
2. **Memory Protection Unit (MPU):** Works in tandem with the MMU to ensure process isolation, strictly preventing one executing process from interfering with or accessing the memory blocks allocated to another.

### II. Bus Hierarchy and Peripheral Connectivity

#### Overview & Theoretical Foundation
Microcontroller peripherals (e.g., ADCs, timers, Ethernet) interface with the core processing unit via dedicated communication buses. Because different peripherals possess varying operating frequencies, data cannot flow directly between disparate bus lines without mediation.

#### Mechanics & Operational Invariants
1. **Bus Categorization:** The system features Advanced High-Speed Buses (AHB1, AHB2) and Advanced Peripheral Buses (APB). High-speed memory and critical peripherals connect to AHB, while standard peripherals connect to APB.
2. **Bridging:** AHB-to-APB bridges synchronize data transfers between buses running at different clock frequencies, preventing data collision and ensuring timing stability.

### III. Register Sets and Execution Modes

#### Overview & Theoretical Foundation
The ARM7 core contains two primary register classifications: General Purpose Registers (GPRs) used by the CPU for loading operands during instruction execution, and Special Function Registers (SFRs) permanently mapped to peripheral control. 

#### Mechanics & Operational Invariants
1. **GPR Distribution:** The architecture has 16 GPRs (R0 to R15).
   * **R13:** Stack Pointer (SP), tracks the top of the stack during context switches.
   * **R14:** Link Register (LR), stores return addresses for preempted processes.
   * **R15:** Program Counter (PC), holds the address of the next instruction.
2. **Execution Modes:** Access to these registers is restricted based on the active operating mode.
   * **User / System Mode:** Full access to all registers; executes standard application code.
   * **FIQ (Fast Interrupt):** High-priority fault handling (e.g., power drops). Access restricted to R8–R15.
   * **IRQ (Interrupt Request):** Standard peripheral interrupts. Access limited to R13–R15.
   * **Supervisor (SVC):** OS-level and bootloader execution. Access limited to R13–R15.
   * **Abort:** Triggers upon invalid memory access attempts. Access limited to R13–R15.
   * **Undefined:** Triggers if an unknown instruction is fed to the decoder. Access limited to R13–R15.

### IV. Pipelining and Branching Execution

#### Overview & Theoretical Foundation
To maximize processing throughput, ARM utilizes a sequential pipelining mechanism. A 4-stage pipeline allows four different instructions to be processed simultaneously in different phases of their lifecycle.

#### Mechanics & Operational Invariants
1. **Pipeline Stages:**
   * **Fetch:** Hardware reads the instruction from memory.
   * **Decode:** Decoder identifies the required operation and instruction type (sequential vs. branch).
   * **Execute:** The ALU processes the decoded operation.
   * **Write-back:** Results are written back to the respective register or memory address.
2. **Branch Flushing:** If the decoder encounters a branch instruction (e.g., function calls, `if-else` loops), it instantly updates the Program Counter with the new target address. The fetcher must flush the erroneously pre-fetched sequential instructions from the pipeline and fetch from the newly updated PC address.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Pipeline Saturation Time** | $\Theta(4)$ | The pipeline reaches maximum parallel efficiency ("pipeline is full") exactly after 4 machine cycles in a 4-stage architecture. |
| **Instruction Execution Time** | $O(1)$ | Due to RISC constraints, every instruction strictly consumes 1 machine cycle (equivalent to 20 clock cycles). |

### V. Exception Handling Workflow

#### Overview & Theoretical Foundation
Exceptions are system anomalies or priority events that pause normal execution. In software, these are managed via `try` (where exceptions are anticipated), `throw` (identifying the exception), and `catch` (the handling logic) blocks. At the hardware level, exceptions trigger an automated context-saving mechanism.

#### Mechanics & Operational Invariants
1. **Interrupt Trigger & Vector Resolution:** An exception halts the main application. The processor consults the Vector Table to retrieve the precise memory address of the required Exception Handler (ISR).
2. **Context Save:** The CPU's current state (PC, LR, SP, and active GPRs) is securely pushed to stack memory.
3. **Execution & Restoration:** The ISR code executes. Upon completion, the CPU retrieves the saved context from the stack, restoring the exact state prior to the interrupt, and resumes normal execution.

### VI. Bare-Metal Programming Setup (STM32F407)

#### Overview & Theoretical Foundation
Bare-metal programming involves bypassing hardware abstraction libraries (HAL) to interact directly with the microcontroller's memory registers. This ensures highly optimized firmware by configuring clock trees and GPIO ports explicitly via bitwise logical operations.

#### Mechanics & Operational Invariants
1. **Identify Hardware Mapping:** Consult the schematic to trace the target peripheral (e.g., LEDs on Port D, Pins 12-15). Identify the bus connection in the datasheet (Port D is mapped to AHB1).
2. **Pointer Initialization:** Locate the base address for the target bus and peripheral in the datasheet. Locate the specific register offsets in the Reference Manual. Combine these to create C-pointers.
3. **Clock Enablement (RCC):** Low-power microcontrollers boot with peripherals asleep. Use the Reset and Clock Control (RCC) AHB1 Enable Register (`AHB1ENR`) to activate the clock for Port D (setting bit #3 via a bitwise `OR` shift: `1 << 3`).
4. **GPIO Mode Configuration:** Configure the GPIO Mode Register. Each pin requires two bits for mode selection (e.g., Pin 12 utilizes bits 24 and 25). Set the bit pair to `01` to designate the pin as an output.
5. **Output Data Register (ODR):** Write to the ODR to toggle the physical pin state. ODR utilizes a 1:1 bit-to-pin mapping, meaning setting bit 12 directly drives Pin 12 high.

# Lecture Study Material: 01 Introduction to Modern Database Systems

## 1. Core Topics For Self-Study

*   **Evolution of Database Technology:** Understanding the progression from manual paper records and file-based systems to Relational, Distributed, NoSQL, and Specialized (Vector/Streaming) databases.
*   **DBMS Architecture & Purpose:** The role of the Database Management System (DBMS) as an interface between applications and physical storage.

## 2. Key Concepts & Definitions

*   **Data:** Raw facts (e.g., a name or a number) that lack meaningful information unless interpreted in a specific context.
*   **Database:** An organized collection of logically related data built for a specific purpose (e.g., banking or university records).
*   **DBMS (Database Management System):** A collection of programs that enables users to create, store, organize, and retrieve data efficiently while serving as an interface between the user and the stored data.
*   **Data Redundancy:** The unnecessary duplication of data in multiple files or locations.
*   **Data Inconsistency:** A state where different versions of the same data exist in different parts of a system, often caused by uncontrolled redundancy.
*   **Concurrency Control:** A mechanism (often lock-based) that manages simultaneous access to data to prevent conflicts and maintain consistency.
*   **Relation:** The formal term for a "Table" in the relational model.
*   **Tuple:** The formal term for a "Row" or "Record" in a table.
*   **Schema:** The description or structure of the database, including table names, column headers, and data types.
*   **Super Key:** A set of one or more attributes that can uniquely identify a record in a relation.
*   **Candidate Key:** A "minimal" super key; a set of attributes that uniquely identifies records without any redundant attributes.
*   **Primary Key:** The specific candidate key chosen by the database designer to uniquely identify tuples in a relation. It cannot contain null values.
*   **Composite Key:** A primary key consisting of more than one attribute.
*   **Foreign Key:** An attribute in a "child" table that refers to the primary key of a "parent" table to establish a relationship between them.
*   **Entity Integrity Constraint:** The rule that no part of a primary key can be NULL.
*   **Referential Integrity Constraint:** The rule ensuring that a value in a foreign key column must either match a value in the referenced primary key column or be NULL.

### II. The Need for Database Systems
*   **The Modern Landscape:** Digital services are driven by data (payments, social media, healthcare).
*   **Volume & Scale:** Data volume doubles roughly every two years, requiring systems that can scale and handle real-time analytics.
*   **Core Functions of a DBMS:**
    *   **Storage:** Physically housing data on hard drives.
    *   **Retrieval:** Fetching specific data via queries.
    *   **Update:** Modifying existing records accurately.
    *   **Security:** Controlling access based on user roles.

### III. Traditional File Systems vs. DBMS
*   **File Systems:** Rely on the operating system's folder/file structure.
*   **Drawbacks of File Systems:**
    *   **Redundancy and Inconsistency:** The same data is stored in multiple files (e.g., Accounts and Academics files both storing student phone numbers). Updates in one file don't reflect in others.
    *   **Difficult Access:** New reports require writing new application programs (hardcoding logic).
    *   **Poor Security:** Limited to basic file permissions; lacks fine-grained role-based access.
    *   **Integrity Issues:** Hard to enforce rules (e.g., age must be 18-60) without complex programming.
*   **DBMS Advantages:**
    *   **Controlled Redundancy:** Data is stored in a centralized location; updates reflect across all departments.
    *   **Backup & Recovery:** Sophisticated log-based recovery from system failures.

### IV. Evolution of Database Technology
*   **1960s:** Manual/Paper-based records.
*   **1970s:** File-based systems.
*   **1970s-Present:** Relational Databases (SQL, tables, rows/columns).
*   **2000s:** Distributed and NoSQL Databases (handling massive volume and flexible schemas).
*   **Modern Era:** Cloud DBs (pay-as-you-go), NewSQL (combining NoSQL scalability with SQL consistency), and Vector Databases (optimized for AI/ML).

### V. Types of Data
1.  **Structured:** Fixed schema, organized in rows/columns (e.g., SQL tables).
2.  **Semi-Structured:** No rigid schema but uses tags/keys (e.g., JSON, XML, HTML). Flexible and extensible.
3.  **Unstructured:** No predefined format (e.g., images, video, audio, text documents). Comprises roughly 80% of modern data.

### VI. The Relational Model and Constraints
*   **Terminology:** A Relation is a Table; a Tuple is a Row; a Schema is the definition.
*   **Keys:**
    *   A **Super Key** is any set of columns that identifies a row.
    *   A **Candidate Key** is the smallest possible super key.
    *   The **Primary Key** is the chosen candidate key.
*   **Constraints:**
    *   **Domain Constraints:** Restrict values to a specific data type or range (e.g., GPA 0.0 to 10.0).
    *   **Entity Integrity:** Primary keys cannot be NULL.
    *   **Referential Integrity:** Foreign keys must point to valid entries in the parent table (prevents "orphan records").

## 4. Discussion & Q&A Highlights

*   **Q: Can there be a centralized file system for all data?**
    *   **Instructor:** Yes, that was the initial thought process. However, the complexities of managing that data, ensuring consistency, and providing an easy query interface are what eventually led to the specialized software we call a DBMS.
*   **Q: Why is it called "Controlled Redundancy" instead of "No Redundancy"?**
    *   **Instructor:** In a relational database, you still need to duplicate some data (like a Student ID) in different tables to link them together. Therefore, redundancy is not 100% eliminated, but it is minimized and managed by the system.
*   **Q: What is the difference between Accuracy and Consistency?**
    *   **Instructor:** Inaccuracy can happen due to both inconsistency (different phone numbers in different files) and integrity violations (entering a GPA of 11.0). Inconsistency is a specific type of inaccuracy where the system holds conflicting data for the same entity.
*   **Q: Can a Foreign Key and a Primary Key be the same in a child table?**
    *   **Instructor:** While possible in some specific designs, generally they are different. A Foreign Key can, however, be part of a **Composite Primary Key** in a child table (e.g., the combination of StudentID and CourseID in an Enrollment table).
*   **Q: Why is a Foreign Key allowed to be NULL?**
    *   **Instructor:** An employee might join a company but hasn't been assigned to a department yet. For those 15 days, the DepartmentID (Foreign Key) in the Employee table remains NULL until the assignment is finalized. This is valid as long as it's not part of the primary key.

## 5. Review & Self-Assessment

### Multiple Choice Questions

**1. Which of the following is a primary characteristic of semi-structured data?**
A) It follows a rigid, predefined tabular schema.
B) It has no organization or metadata whatsoever.
C) it uses tags and key-value pairs to provide self-describing structure.
D) It is primarily comprised of audio and video files.
*Answer: C. Explanation: Semi-structured data like JSON or XML uses tags or keys rather than a fixed tabular schema.*

**2. The Entity Integrity Constraint states that:**
A) A foreign key must match a primary key in a parent table.
B) No part of a primary key can be NULL.
C) Data must fall within a specific range (e.g., age 18-60).
D) A table cannot have more than one candidate key.
*Answer: B. Explanation: Entity integrity ensures that every record is uniquely identifiable, which is impossible if the primary key is null.*

**3. What is a "Minimal Super Key" formally called?**
A) Primary Key
B) Composite Key
C) Candidate Key
D) Foreign Key
*Answer: C. Explanation: A candidate key is a super key from which you cannot remove any attribute without losing the property of uniqueness.*

**4. Which problem occurs in file-based systems when a student's phone number is updated in the "Academics" file but remains the old number in the "Accounts" file?**
A) Unstructured data
B) Referral Error
C) Data Inconsistency
D) Domain Violation
*Answer: C. Explanation: Inconsistency refers to conflicting versions of the same data being present in the system.*

**5. A "Relation" in the relational model represents a:**
A) Row
B) Column
C) Table
D) Database
*Answer: C. Explanation: In formal relational database terminology, a relation is synonymous with a table.*

### Conceptual Problems

**1. Explain the "Hardcoding" problem in traditional file systems and how a DBMS solves it.**
*Answer: In file systems, the structure of the data is embedded directly into the application program logic. If the file format changes (e.g., adding a new field), every program using that file must be manually rewritten. A DBMS introduces "Data Abstraction," separating the physical data storage from the conceptual view, allowing users to query data via SQL without needing to know the underlying file format.*

**2. Describe a scenario where a Composite Primary Key is necessary.**
*Answer: In an "Enrollment" table, a StudentID alone cannot be the primary key because one student takes many courses. Similarly, a CourseID alone cannot be the primary key because many students take one course. A composite primary key consisting of both (StudentID, CourseID) is required to uniquely identify a specific enrollment record.*

**3. Why are Vector Databases becoming increasingly relevant in the modern era?**
*Answer: Traditional relational databases are not optimized for similarity searches in high-dimensional data. Vector databases store data as "vector embeddings," allowing for similarity searches, which are crucial for AI-driven applications like semantic search, recommendation systems, and Large Language Models (LLMs).*

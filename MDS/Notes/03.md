## 2. Key Concepts & Definitions

*   **Primary Key (PK):** A unique identifier for a record in a table; cannot be null.
*   **Foreign Key (FK):** An attribute in one table that refers to the Primary Key of another table, establishing a link.
*   **Referential Integrity:** A set of rules ensuring that relationships between tables remain consistent (e.g., you cannot have an employee in a non-existent department).
*   **Second Normal Form (2NF):** Requires the table to be in 1NF and all non-prime attributes to be fully functionally dependent on the entire candidate key (no partial dependencies).
*   **Third Normal Form (3NF):** Requires the table to be in 2NF and all non-prime attributes to be non-transitively dependent on the candidate key (no A $\rightarrow$ B $\rightarrow$ C relationships).
*   **DDL (Data Definition Language):** Commands that define the database structure (e.g., `CREATE`, `ALTER`, `DROP`).
*   **DML (Data Manipulation Language):** Commands used to manage data within the objects (e.g., `INSERT`, `UPDATE`, `DELETE`).
*   **DQL (Data Query Language):** Commands used to retrieve data (primarily `SELECT`).
*   **TCL (Transaction Control Language):** Commands to manage database transactions (e.g., `COMMIT`, `ROLLBACK`).
*   **DCL (Data Control Language):** Commands used for permissions and access control (e.g., `GRANT`, `REVOKE`).
*   **CHAR(n):** Fixed-length character string. If the data is shorter than *n*, it is padded with spaces.
*   **VARCHAR(n):** Variable-length character string. It only occupies as much space as the data provided (up to a maximum *n*).
*   **Wildcards:** 
    *   `%`: Represents zero or more characters.
    *   `_`: Represents exactly one character.
*   **DECIMAL(M, D):** A fixed-point number where *M* is the total number of digits and *D* is the number of digits after the decimal point.

## 3. Detailed Structured Lecture Notes

### I. Normalization and Integrity Recap
*   **Referential Integrity Issues:** Using independent tables can lead to "orphaned" data. For example, an employee assigned to "Department 4" when the Department table only lists departments 1, 2, and 3.
*   **Foreign Key Enforcement:** Declaring a Foreign Key prevents the insertion of invalid references.
*   **2NF vs. 3NF:**
    *   **2NF:** Eliminates partial dependencies. If a table has a composite primary key (e.g., SSN + ProjectNumber), attributes like "Employee Name" (dependent only on SSN) must be moved to a separate table.
    *   **3NF:** Eliminates transitive dependencies. If SSN $\rightarrow$ DeptNumber and DeptNumber $\rightarrow$ DeptName, then "DeptName" must be moved to a separate Department table.
*   **Decomposition and Joins:** Normalization involves "decomposing" one large table into smaller ones. SQL Joins are used to "revert" this process to view the original unified data.

### II. Introduction to SQL
*   **Purpose:** SQL provides a logical interface between the application/user and the physical storage.
*   **DBMS Interaction:**
    1.  User sends an SQL statement.
    2.  DBMS Query Processor parses and interprets the query.
    3.  Optimizer creates an execution plan.
    4.  Storage Manager retrieves data from physical disks.
*   **Efficiency:** SQL allows for complex analytics, updates, and controlled access through permissions.

### III. Data Definition Language (DDL)
*   **Database Management:**
    *   `SHOW DATABASES;`: Lists available databases.
    *   `CREATE DATABASE test;`: Creates a new workspace.
    *   `USE test;`: Sets the active database.
    *   `DROP DATABASE test;`: Deletes the workspace.
*   **Table Creation:**
    *   Syntax: `CREATE TABLE table_name (column1 datatype constraints, ...);`.
    *   **Constraints:** `NOT NULL` (requires a value), `PRIMARY KEY`, `DEFAULT` (sets a value if none is provided), and `CHECK` (limits value ranges).
    *   **Referential Integrity Syntax:** `FOREIGN KEY (col) REFERENCES parent_table(parent_col) ON DELETE SET NULL ON UPDATE CASCADE`.
*   **Modifying Tables:**
    *   `ALTER TABLE table_name ADD column_name datatype;`: Adds a new attribute.
    *   `ALTER TABLE table_name DROP COLUMN column_name;`: Removes an attribute.
    *   `DROP TABLE table_name;`: Deletes the entire table structure.

### IV. Data Manipulation Language (DML)
*   **Insertion:**
    *   `INSERT INTO table VALUES (val1, val2...);`: Requires values for every column in order.
    *   `INSERT INTO table (col1, col3) VALUES (val1, val3);`: Allows skipping columns that allow nulls or have defaults.
*   **Updating:** `UPDATE table_name SET column = new_value WHERE condition;`. 
    *   *Warning:* Forgetting the `WHERE` clause updates every row in the table.
*   **Deletion:** `DELETE FROM table_name WHERE condition;`.
    *   *Warning:* `DELETE FROM table_name;` without a `WHERE` clause truncates all data.

### V. Data Query Language (DQL) & Data Retrieval
*   **Basic Selection:** `SELECT column1, column2 FROM table;`. Use `*` to select all columns.
*   **Filtering:** Use the `WHERE` clause with operators like `=`, `<`, `>`, `!=`, `IN`, `AND`, `OR`.
*   **Pattern Matching:** `WHERE column LIKE '%pattern%';`. Useful for finding partial strings (e.g., addresses containing "Noida" or years within a date).
*   **Aggregates and Groups:**
    *   **Aggregates:** `SUM()`, `AVG()`, `COUNT()`, `MAX()`, `MIN()`.
    *   **GROUP BY:** Collapses rows into summary rows based on shared values (e.g., counting employees per department).
    *   **HAVING:** Acts as a `WHERE` clause for groups. (e.g., "Find departments having more than 5 employees").
*   **Ordering:** `ORDER BY column ASC/DESC;`. Multiple columns can be used (e.g., order by Last Name, then First Name).

### VI. SQL Joins
*   **Mechanism:** Links rows from two or more tables based on a related column.
*   **Aliases:** Using short letters (e.g., `FROM Employee E, Department D`) makes queries readable and prevents ambiguity when column names overlap.
*   **Example Join:** `SELECT E.Fname, D.Dname FROM Employee E, Department D WHERE E.Dno = D.Dnumber;`. This identifies which department each employee belongs to by name.
*   **Mathematical Operations:** SQL allows calculations within the Select statement (e.g., `SELECT Salary * 1.1 AS Increased_Salary`).

### VII. Transaction and Integrity Logic
*   **On Delete Actions:**
    *   `SET NULL`: If the parent record (e.g., a Department) is deleted, the child reference (Employee's Dno) becomes null.
    *   `CASCADE`: If a parent ID is updated, the child records update automatically.
*   **Integrity Constraints:** `CHECK (Dnumber > 0 AND Dnumber < 21)` ensures logical data entry at the schema level.
*   **ACID Properties:** Mentioned as essential for reliable transaction execution (Atomicity, Consistency, Isolation, Durability).

## 3. Key Concepts & Formal Definitions

| Concept / Term | Formal Definition & Operational Meaning | Contextual Constraints / Properties |
| :--- | :--- | :--- |
| **Nonlinear Data Structure** | A data organization scheme where elements are connected non-sequentially, establishing hierarchical or network-based one-to-many or many-to-many relationships. | Traversal paths are non-linear and multiple; typically requires reference- or pointer-based non-contiguous memory. |
| **Tree** | A nonlinear hierarchical data structure composed of nodes connected by directed edges, maintaining exactly one path between the root and any node without containing cycles. | An $N$-node tree contains strictly $N-1$ edges. |
| **Root Node** | The topmost node of a tree hierarchy that possesses no parent node and serves as the universal entry point for all operations. | Unique per tree; situated by convention at Level $0$ (Depth $0$). |
| **Leaf Node (External Node)** | Any node in the tree structure that has zero child nodes. | Serves as path termination in traversals; stores operands in expression trees and unique character assignments in Huffman trees. |
| **Internal Node** | Any node having at least one child and (with the exception of the root) a valid parent node. | Encapsulates routing ranges in index trees and operators in expression trees. |
| **Degree of a Node** | The count of children connected directly under that specific node (when parent link is excluded). | For general trees, unrestricted; for binary trees, maximum degree is $2$ (or $3$ if incoming parent edge is counted). |
| **Height of a Node** | The total number of edges traversed along the longest downward path from that node to a leaf. | The height of a leaf node is $0$; the height of the tree is the height of the root. |
| **Binary Tree** | A hierarchical tree structure where every node has at most two children, explicitly designated as the left child and right child. | Maximum nodes at level $x$ is $2^x$. |
| **Full Binary Tree** | A binary tree where every single node has either zero children or exactly two children. | No node is permitted to possess exactly one child. Number of leaves $L = I + 1$ (where $I$ includes the root). |
| **Complete Binary Tree** | A binary tree where all levels are fully occupied, except possibly the final level, which must be filled strictly sequentially from left to right. | Height of an $N$-node complete binary tree is $\lfloor \log_2 N \rfloor$. |
| **Perfect Binary Tree** | A binary tree in which all internal nodes have exactly two children, and all leaf nodes reside strictly at the identical lowest level. | Total nodes $N = 2^{h+1} - 1$; exactly $2^h$ leaf nodes. |
| **Balanced Binary Tree** | A binary tree where the height differential between the left and right subtrees of every single node is bounded within an invariant limit (e.g., $|\text{height}_L - \text{height}_R| \le 1$ in AVL trees). | Enforces an overall tree height bound of $O(\log N)$, preventing worst-case linear skew. |
| **Binary Search Tree (BST)** | A binary tree adhering to a strict symmetric key-ordering invariant: for every node $x$ with key $K$, all keys in the left subtree of $x$ are strictly less than $K$, and all keys in the right subtree are strictly greater than $K$. | Enables binary-search-like decision routing; duplicates handled by localized convention (e.g., $\le$ on left or right). |

## 4. Detailed Structured Technical Lecture Notes

### I. Foundations of Nonlinear Data Structures

#### Overview & Theoretical Foundation
Linear data structures—such as arrays, linked lists, stacks, and queues—enforce an unambiguous, sequential entry and exit ordering where elements exhibit one-to-one predecessor and successor relationships. While memory layout is contiguous or sequentially linked, linear organization fails to represent naturally hierarchic, categorized, or networked relationships. 

Nonlinear data structures arrange elements non-sequentially, supporting one-to-many relationships (as observed in hierarchical trees) or many-to-many relationships (as seen in graph networks). Data placement is driven by structural criteria or semantic keys rather than arrival order. This architectural paradigm optimizes search, retrieval, and targeted modifications across large data stores, while introducing traversal complexity and structural pointer maintenance.

```
       Linear Topology:
       [Elem 0] <---> [Elem 1] <---> [Elem 2] <---> [Elem 3]

       Hierarchical Nonlinear Topology (Tree):
                        [ Root ]
                        /      \
                  [Node B]    [Node C]
                  /      \        \
              [Node D]  [Node E]  [Node F]
```

#### Comparison of Structural Paradigms
| Structural Dimension | Linear Data Structures | Nonlinear Data Structures |
| :--- | :--- | :--- |
| **Element Arrangement** | Sequential / sequential-adjacent ordering | Hierarchical or networked multi-dimensional ordering |
| **Relational Model** | 1-to-1 (unique predecessor and successor, except endpoints) | 1-to-many (Tree parent-to-children) or many-to-many (Graph vertices) |
| **Traversal Paths** | Single, deterministic path | Multiple valid traversal trajectories |
| **Memory Allocation** | Contiguous blocks or linear sequential pointer chains | Pointer-based linked nodes or non-contiguous references |
| **Implementation Complexity** | Simple to implement and maintain | Complex pointer updates and rebalancing requirements |
| **Element Accessibility** | Direct via linear offset or sequential next/prev access | Path-dependent access originating from root or entry vertex |
| **Structural Overhead** | Minimal auxiliary memory overhead | Higher overhead due to multiple structural edge/child pointers |
| **Canonical Examples** | Arrays, Singly/Doubly Linked Lists, Stacks, Queues | General Trees, Binary Trees, Heaps, Graphs |

### II. Tree Architecture: Domain Applications & Structural Mechanics

#### Overview & Theoretical Foundation
A tree represents hierarchical dependencies where every child is subordinate to an identifiable parent. The structural utility of trees spans systems programming, compilation, database theory, and network transmission.

```
                        Expression: (A + B) * (C - D) / E

                                    [ / ]  <-- Root
                                   /     \
                                [ * ]    [ E ]
                               /     \
                            [ + ]   [ - ]
                            /   \   /   \
                           [A] [B] [C] [D]  <-- Leaves (Operands)
```

#### Real-World Operational Modalities
1. **Operating System File Structures:** Directories and sub-directories map directly to a tree. The system drive (e.g., `C:\`) acts as the root node, folders serve as internal nodes, and non-directory files act strictly as terminal leaf nodes unable to host subordinate files.
2. **Document Object Model (DOM) & Markups:** Browsers parse HTML and XML into hierarchical DOM trees where outer container tags parent inner nested tags.
3. **Compiler Expression & Parse Trees:** Arithmetic and grammatical expressions map into syntax trees. In arithmetic expression trees:
   * **Leaf Nodes:** Represent operands (constants, variables such as $A, B, C, D, E$).
   * **Internal Nodes:** Represent operators ($+, -, *, / $).
   * Operational evaluation proceeds recursively from leaves upwards. For $((A + B) * (C - D)) / E$, sub-operations $A + B$ and $C - D$ execute prior to multiplication, which subsequently acts as the left operand to the root division operator.
   * Parse trees validate source strings against context-free grammar production rules (e.g., $E \to E + T$) during compiler semantic analysis.
4. **Database Indexing (B-Trees):** Physical storage is mapped to multi-way search trees (B-Trees) aligned with disk block/page boundaries. Keys within nodes serve as operational range dividers:
   * A node hosting key range boundaries $[60, 90]$ splits searches into three pointer branches: items $< 60$ traverse the left subtree; items between $60$ and $90$ traverse the center subtree; items $> 90$ traverse the right subtree.
   * Expanding key capacity per node (e.g., $[60, 70, 90]$ creating four child branches) decreases the tree's height, drastically minimizing disk seek latencies down to $O(\log N)$.
5. **Network Routing Frameworks:** Routers route packet data through hierarchical tree topographies running from high-capacity core routers down through distribution routers, local access switches, and terminal client host devices.
6. **Data Compression via Huffman Coding:** Generates variable-length prefix-free binary codes using character occurrence frequencies:
   * Characters with maximum frequency are placed nearest to the root, obtaining minimal bit lengths.
   * Path branching assigns bit $0$ to the left branch and bit $1$ to the right branch.
   * **Prefix-Free Property:** Codes are assigned strictly at terminal leaf nodes. Because a leaf has no child branches, no valid code can form a leading prefix of any other valid character code, ensuring unambiguous, uniquely decodable streams.

### III. Binary Tree Taxonomy, Formal Invariants, and Mathematical Proofs

#### Overview & Theoretical Foundation
A Binary Tree is a specialized tree wherein no node can exceed a branching factor of two. Nodes host a left child, a right child, both, or neither. Based on level completion and balancing constraints, binary trees are categorized into Full, Complete, Perfect, and Balanced topologies.

```
       Full Binary Tree             Complete Binary Tree            Perfect Binary Tree
            ( 1 )                          ( 1 )                           ( 1 )
           /     \                        /     \                         /     \
        ( 2 )   ( 3 )                  ( 2 )   ( 3 )                   ( 2 )   ( 3 )
        /   \                          /   \   /                       /   \   /   \
      (4)   (5)                      (4)  (5) (6)                    (4)  (5) (6)  (7)
```

#### Taxonomy Comparison & Boundary Invariants
| Classification | Structural Invariant Criteria | Permissible Children Per Node | Single Child Permitted? | Key Ordering Required? |
| :--- | :--- | :--- | :--- | :--- |
| **Binary Tree (General)** | Degree bounded by 2 per node | $0, 1, 2$ | Yes | No |
| **Binary Search Tree** | Symmetric key ordering: $\text{Left} < \text{Root} < \text{Right}$ | $0, 1, 2$ | Yes | Strictly Required |
| **Full Binary Tree** | Nodes must have zero or two children | $0$ or $2$ strictly | No | No |
| **Complete Binary Tree** | Levels $0 \le \ell < h$ fully filled; level $h$ packed sequentially left-to-right | $0, 1, 2$ | Yes (at boundary of last level) | No |
| **Perfect Binary Tree** | All internal nodes possess degree 2; all leaves reside at exact height $h$ | $0$ or $2$ strictly | No | No |
| **Balanced Binary Tree** | Height differentials between left and right subtrees stay bounded ($\le k$) | $0, 1, 2$ | Yes | No (unless balanced BST) |

#### Structural Mathematical Bounds (for Height $h$)
Let height $h$ denote the edge count along the longest downward path from root to leaf, where the root level is defined as $\ell = 0$.

1. **Maximum Node Density at Level $x$:**
   $$N_{\max}(x) = 2^x$$
2. **Maximum Cumulative Nodes in a Tree of Height $h$:**
   $$N_{\max} = \sum_{x=0}^h 2^x = 2^{h+1} - 1$$
3. **Minimum Cumulative Nodes in a Tree of Height $h$:**
   To sustain a path length of $h$, each level from $0$ through $h$ must host at least one node:
   $$N_{\min} = h + 1$$
4. **Maximum Leaf Count at Height $h$:**
   Leaves reside at level $h$:
   $$L_{\max} = 2^h$$
5. **Edge Invariant for an $N$-Node Tree:**
   Because every node except the root possesses exactly one incoming directed edge from its parent, and trees are strictly acyclic:
   $$E = N - 1$$
6. **Leaf-to-Internal Invariant in Full Binary Trees:**
   Let $L$ be the count of leaf nodes, and $I$ be the count of internal nodes including the root. Every internal node produces 2 children:
   $$N = I + L$$
   Total child edges originating from internal nodes equals $2I$. Since every non-root node has one incoming edge:
   $$N - 1 = 2I \implies (I + L) - 1 = 2I \implies L = I + 1$$
   * Total nodes $N = I + (I + 1) = 2I + 1 = 2L - 1$.
   * Total edges $E = N - 1 = 2I = 2L - 2$.
7. **Node Envelope for Complete Binary Trees:**
   If height is $h$, levels $0$ through $h-1$ are fully populated ($2^h - 1$ nodes). The final level $h$ holds between $1$ and $2^h$ nodes:
   $$N \in [2^h, 2^{h+1} - 1]$$
   Solving for height yields:
   $$h = \lfloor \log_2 N \rfloor$$

### IV. Memory Representations & Core Algorithmic Mechanics

#### Overview & Theoretical Foundation
Binary trees are realized through two standard implementation models: contiguous array representations and pointer-linked representations. Array-based layouts calculate relationships arithmetically without explicit storage for edges, but suffer from memory fragmentation when handling unbalanced or skewed structures. Pointer-based layouts allocate dynamic memory per node, achieving optimal spatial usage for sparse topologies at the cost of pointer storage overhead.

```
       Array Mapping (Contiguous Buffer):
       Tree:       (A) [idx 0]
                  /   \
        (B) [idx 1]   (C) [idx 2]
        /
       (D) [idx 3]

       Buffer: [ A | B | C | D | NULL | NULL | NULL ]
       Index:    0   1   2   3     4      5      6

       Linked Representation (Pointer Node):
       +---------------+----------------+----------------+
       | *left_child   |   data_value   | *right_child   |
       +---------------+----------------+----------------+
```

#### Array-Based Mathematical Mapping
For a 0-indexed array where the root element resides at index $i = 0$:
* **Left Child Index:** $\text{Left}(i) = 2i + 1$
* **Right Child Index:** $\text{Right}(i) = 2i + 2$
* **Parent Node Index:** $\text{Parent}(i) = \lfloor \frac{i - 1}{2} \rfloor$

*(Note: For 1-indexed implementations, Left is $2i$, Right is $2i + 1$, and Parent is $\lfloor i/2 \rfloor$).*

#### Algorithmic Implementations (Array Representation)

```
// 1. Finding the Parent Index
Algorithm FindParent(Array A, Size N, Key K):
    pos = -1
    For i = 0 to N - 1:
        If A[i] == K:
            pos = i
            Break
    If pos == -1:
        Output "Node not found"
        Return NULL
    If pos == 0:
        Output "Root has no parent"
        Return NULL
    parentIndex = Floor((pos - 1) / 2)
    Return parentIndex

// 2. Inserting a Node
Algorithm InsertChild(Array A, Size N, Key targetKey, Object newObject):
    targetIndex = Search(A, targetKey)
    If targetIndex == -1 Or A[targetIndex] == NULL:
        Output "Target key not found. Search unsuccessful."
        Return
    
    leftIndex = 2 * targetIndex + 1
    rightIndex = 2 * targetIndex + 2
    
    If leftIndex < N And A[leftIndex] == NULL:
        A[leftIndex] = newObject
    Else If rightIndex < N And A[rightIndex] == NULL:
        A[rightIndex] = newObject
    Else:
        Output "Insertion failed: Both child positions occupied."

// 3. Deleting a Node (Restricted to Leaves)
Algorithm DeleteLeaf(Array A, Size N, Key targetKey):
    targetIndex = Search(A, targetKey)
    If targetIndex == -1 Or A[targetIndex] == NULL:
        Output "Target key not found."
        Return
    
    leftIndex = 2 * targetIndex + 1
    rightIndex = 2 * targetIndex + 2
    
    isLeftNull = (leftIndex >= N) Or (A[leftIndex] == NULL)
    isRightNull = (rightIndex >= N) Or (A[rightIndex] == NULL)
    
    If isLeftNull And isRightNull:
        A[targetIndex] = NULL
    Else:
        Output "Deletion failed: Key is not a leaf node."

// 4. Calculating Degree of a Node
Algorithm GetDegree(Array A, Size N, Key K):
    pos = Search(A, K)
    If pos == -1 Or A[pos] == NULL:
        Output "Node not found"
        Return -1
    
    degree = 0
    leftIndex = 2 * pos + 1
    rightIndex = 2 * pos + 2
    
    If leftIndex < N And A[leftIndex] != NULL:
        degree = degree + 1
    If rightIndex < N And A[rightIndex] != NULL:
        degree = degree + 1
        
    Return degree

// 5. Recursive Height Calculation
Algorithm CalculateHeight(Array A, Size N, Index i):
    If i >= N Or A[i] == NULL:
        Return -1
    
    leftHeight = CalculateHeight(A, N, 2 * i + 1)
    rightHeight = CalculateHeight(A, N, 2 * i + 2)
    
    Return 1 + Max(leftHeight, rightHeight)
```

### V. Traversal Algorithms: Mechanics and Orderings

#### Overview & Theoretical Foundation
Tree traversal is the process of visiting every node within the hierarchy exactly once. Unlike linear structures, trees can be walked along multiple dimensional vectors. Traversal strategies divide into Depth-First Search (DFS) orderings—characterized by whether the root/parent is processed before, between, or after its subordinate subtrees—and Breadth-First Search (BFS), which reads nodes level by level.

#### Depth-First Traversals
* **Preorder Traversal ($\text{Root} \to \text{Left} \to \text{Right}$):** Inspects the root prior to recursive calls down the left and right subtrees. Corresponds directly to mathematical Prefix notation.
* **Inorder Traversal ($\text{Left} \to \text{Root} \to \text{Right}$):** Recurses through the left subtree, processes the current root upon returning, and then recurses down the right subtree. Corresponds to Infix notation. For Binary Search Trees, inorder traversal produces an ascending, sorted key sequence.
* **Postorder Traversal ($\text{Left} \to \text{Right} \to \text{Root}$):** Fully evaluates both left and right subtrees before printing or deallocating the parent root. Corresponds to Postfix (Reverse Polish) notation; essential for post-order syntax evaluation and bottom-up recursive destructuring.

#### Breadth-First Traversal
* **Level-Order Traversal:** Evaluates horizontal node slices sequentially from Level $0$ to Level $h$, processing nodes left-to-right within each level slice. Implemented using an auxiliary First-In, First-Out (FIFO) queue:
  1. Enqueue root node.
  2. While queue is non-empty, dequeue front element $u$, record $u$'s data, and enqueue $u$'s left and right children if they exist.

#### Mechanical Walkthrough on Reference Tree
Given the lecture reference tree:
```
           ( A )
          /     \
       ( B )   ( C )
       /   \   /   \
     (D)   (E)(F)  (G)
```

* **Preorder Execution Trace:**
  $$\text{Path: } A \to B \to D \to E \to C \to F \to G$$
* **Inorder Execution Trace:**
  $$\text{Path: } D \to B \to E \to A \to F \to C \to G$$
* **Postorder Execution Trace:**
  $$\text{Path: } D \to E \to B \to F \to G \to C \to A$$
* **Level-Order Execution Trace:**
  $$\text{Queue Pop Sequence: } [A] \to [B, C] \to [D, E, F, G]$$
  $$\text{Result: } A \to B \to C \to D \to E \to F \to G$$

### VI. Algorithmic Analysis, Design Trade-offs & Systems Constraints

#### Algorithmic Complexity Profile
| Operation | Bound | Theoretical Condition & Justification |
| :--- | :--- | :--- |
| **Search (Unordered Binary Tree)** | $O(N)$ | Arbitrary key distribution requires traversing both subtrees across all $N$ nodes. |
| **Search (Balanced BST / B-Tree)** | $O(\log N)$ | Symmetric key ordering divides search space by half at each comparison step. |
| **Search (Degenerate Skewed BST)**| $O(N)$ | Pathological insertion sequence creates a single linked chain of height $N-1$. |
| **Parent Lookup (Array)** | $O(1)$ | Direct mathematical evaluation of parent index via $\lfloor (i - 1) / 2 \rfloor$ after node lookup. |
| **Tree Traversal (All orders)** | $\Theta(N)$ | Every node is queued, pushed to stack, and evaluated exactly once. |
| **Auxiliary Memory (DFS Recursion)** | $O(h)$ | Call stack depth scales with maximum tree height ($O(\log N)$ best, $O(N)$ worst). |
| **Auxiliary Memory (BFS Queue)** | $O(W)$ | Proportional to maximum level width ($W \le 2^h$, up to $\approx \lceil N/2 \rceil$ leaves). |

#### Implementation Design Trade-offs

```
      Array Layout Memory Inefficiency (Skewed Tree):
      Tree:  (A)
               \
               (B)
                 \
                 (C)
      Indices: 0 -> 2 -> 6 (Nodes: 3 | Array Size Allocated: 7 | Wasted Slots: 4)
```

* **Array-Based vs. Pointer-Based Trade-offs:**
  * **Memory Overhead:** Array representation eliminates pointer fields (saving $2 \times \text{sizeof}(\text{pointer})$ per node) and supports $O(1)$ mathematical index transitions between parents and children. However, in incomplete or skewed trees, absent nodes still consume index locations. A right-skewed tree of height $h$ requires an array size of $2^{h+1}-1$ to store only $h+1$ nodes, wasting exponential memory space.
  * **Dynamic Scalability:** Array capacity is static, demanding costly buffer reallocation and data migrations ($O(N)$ copy overhead) when tree height exceeds pre-allocated bounds. Linked implementations dynamically allocate individual nodes on the heap at $O(1)$ allocation cost, utilizing memory strictly when nodes are inserted.
* **Database Paging Considerations (B-Trees vs. BSTs):**
  * Binary Search Trees distribute nodes across memory addresses, incurring cache misses and high disk seek latencies during secondary storage access.
  * B-Trees pack multiple sorted keys and children into node blocks matching disk page dimensions (e.g., 4KB), reducing overall tree height to $O(\log_B N)$ and cutting down high-latency physical disk I/O operations.

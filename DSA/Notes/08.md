## 4. Detailed Structured Technical Lecture Notes

### I. Expression Trees & Notation Equivalence

#### Overview & Theoretical Foundation
An expression tree is an explicit binary tree abstraction of a mathematical expression. Binary operators act as root nodes for their respective sub-operations, while variables and numerical literals populate the leaf nodes. Expression trees eliminate structural ambiguity such as operator precedence and associativity without needing explicit parentheses. By applying standard depth-first traversals over the constructed expression tree, standard arithmetic notations emerge naturally: In-order traversal yields standard Infix notation, Pre-order traversal yields Prefix (Polish) notation, and Post-order traversal yields Postfix (Reverse Polish) notation. Prefix and Postfix notations are completely free from parentheses, allowing linear single-pass evaluation by computing engines.

#### Mechanics & Operational Invariants
1. **Step-by-Step Construction Procedure:**
   * Identify the primary (outermost/lowest precedence) operator within the expression to establish the root node (e.g., in $(A + B \times C / D) \times (E - F + G)$, the center multiplication $\times$ forms the root).
   * Divide the expression into left and right sub-expressions flanking the primary operator.
   * Recursively locate the primary operator within each sub-expression to spawn child operator nodes (e.g., $+$ on the left branch, $-$ on the right branch).
   * Assign atomic operands as terminating leaf nodes.
2. **Traversal Extraction:**
   * **In-order ($L \to Root \to R$):** Yields the Infix expression. Parentheses must be reintroduced according to tree depth to preserve precedence.
   * **Pre-order ($Root \to L \to R$):** Yields the Prefix expression directly without parentheses.
   * **Post-order ($L \to R \to Root$):** Yields the Postfix expression directly without parentheses.

### II. Binary Heap Structures & Priority Queues

#### Overview & Theoretical Foundation
A binary heap is a complete binary tree that maintains a strict hierarchical heap-order invariant. In a Max Heap, every parent node possesses a value greater than or equal to its children, guaranteeing that the global maximum resides at the root. Conversely, in a Min Heap, every parent node possesses a value less than or equal to its children, anchoring the global minimum at the root. Heaps do not enforce a horizontal binary search ordering: a left child is not constrained to be smaller than a right child. Because heaps are structurally complete binary trees, they can be implemented using contiguous 1D arrays or dynamically linked nodes. When linked structures are utilized without direct random index access, tree navigation from the root to the dynamically changing insertion or deletion boundary relies on the binary representation of the node’s position index.

#### Mechanics & Operational Invariants
1. **Bitwise Positional Navigation for Linked Heaps:**
   * Maintain a global counter $N$ denoting the total number of elements.
   * To locate the insertion point for node $N + 1$ (or find the last node $N$ during deletion), convert the target integer position into its binary representation.
   * Strip off the most significant bit (MSB), which represents the root.
   * Read the remaining bits sequentially from left to right: a bit value of `0` instructs a transition to the left child (`node = node.left`), while a bit value of `1` instructs a transition to the right child (`node = node.right`).
   * *Example:* For target position $N = 8$ ($1000_2$), dropping the MSB yields `000`. Starting at the root, the path proceeds Left $\to$ Left $\to$ Left. For position $5$ ($101_2$), dropping the MSB yields `01`, navigating Left $\to$ Right.
2. **Insertion Routine (Sift-Up):**
   * Check if capacity is exhausted.
   * Append the new element at the leaf position $N + 1$ via bitwise navigation or array index $N + 1$.
   * Compare the newly inserted node's value with its parent:
     * For a Max Heap, if the node's value exceeds its parent, swap values.
     * Continue swapping upward iteratively or recursively until the parent is greater than or equal to the node, or the node becomes the root.
3. **Deletion Routine (Sift-Down / Heapify):**
   * Verify whether the heap is empty (underflow check).
   * Extract the root value (the maximum in a Max Heap or minimum in a Min Heap).
   * Swap the root node’s value with the terminal leaf node at position $N$.
   * Decrement the element count: $N \leftarrow N - 1$.
   * Restore the heap invariant by invoking `heapify` downward from the root:
     * Evaluate the node against its left and right children.
     * Identify the largest child (in a Max Heap). If the largest child exceeds the current node, swap their values.
     * Update the active pointer to the swapped child position and repeat downward until no child is larger or a leaf is reached.
4. **Boundary & Edge Cases:**
   * **Empty Heap:** Deletion halts immediately without execution.
   * **Single Element:** Heapify terminates trivially at the root.
   * **Full Capacity:** Array-backed implementations abort insertion if allocated space is exhausted.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Best-Case Time (Heapify)** | $\Omega(1)$ | Occurs when the replaced node at the target position already satisfies the heap property relative to its children, requiring zero swaps. |
| **Worst-Case Time (Heapify)** | $O(\log N)$ | Occurs when an element violates the heap condition across every tier, forcing a full traversal from root to leaf along the tree height $h = \lfloor \log_2 N \rfloor$. |
| **Average-Case Time (Heapify)** | $\Theta(\log N)$ | Standard descent through the levels of a balanced complete binary tree. |
| **Heap Sort Time Complexity** | $O(N \log N)$ | Sorting requires $N$ successive root extraction and deletion passes, each triggering a downward sift taking worst-case $O(\log N)$ time: $N \times O(\log N) = O(N \log N)$. |
| **Space Complexity** | $O(1)$ auxiliary | Array-based implementations sort in-place; pointer-based updates require constant tracking variables. |

#### Design Trade-offs & Limitations
Binary heaps operate as the algorithmic engine for Priority Queues, where jobs or processes must be dispatched dynamically based on priority levels rather than insertion sequence (FIFO). While heaps provide rapid $O(1)$ retrieval of the extremum and $O(\log N)$ updates, they do not support arbitrary efficient element searches, which require $O(N)$ linear scans due to the lack of horizontal ordering constraints between sibling branches.

### III. Graph Fundamentals, Taxonomies, and Traversals

#### Overview & Theoretical Foundation
A graph $G = (V, E)$ is a general non-linear discrete structure comprising a set of vertices $V$ and interconnecting edges $E$. Unlike trees, graphs do not enforce single-parent hierarchies, unique root origins, or acyclic invariants. In formal terms, every tree is fundamentally a graph (specifically, a connected, acyclic graph), but not all graphs are trees. Graphs model symmetric interactions (undirected graphs such as mutual connections or two-way roads) or asymmetric dependencies (directed graphs such as web citations, hierarchical reporting, or workflows).

#### Mechanics & Operational Invariants

```
Graph Walk Taxonomies:
Walk (General sequence of alternate vertices and edges)
 ├── No Repeated Edges   ──> Trail
 │                            └── Closed (Start == End) ──> Circuit
 └── No Repeated Vertices ──> Path
                              └── Closed (Start == End) ──> Cycle
```

1. **Topological Variations:**
   * **Simple Graph:** Disallows both parallel edges between identical vertex pairs and self-loops.
   * **Multigraph:** Permits multiple parallel edges between vertex pairs (e.g., multiple transit lines or flight paths connecting identical destinations).
   * **Pseudograph:** Permits self-loops (e.g., state machines in finite automata returning to the current state).
   * **Bipartite Graph:** Partitions $V$ into disjoint subsets $V_1$ and $V_2$ such that internal edges within $V_1$ or within $V_2$ are strictly absent. A complete bipartite graph connects every node in $V_1$ directly to every node in $V_2$.
   * **Complete Undirected Graph ($K_n$):** A simple undirected graph where every distinct vertex pair is linked by an edge. The exact number of edges required for $n$ vertices is given by:
     $$E = \frac{n(n - 1)}{2}$$
2. **Graph Traversals:**
   * **Breadth-First Search (BFS):**
     * Employs a First-In, First-Out (FIFO) **Queue**.
     * Enqueue the starting vertex and mark it as visited.
     * While the queue is non-empty: Dequeue vertex $u$; iterate through all adjacent vertices $v \in Adj[u]$; if $v$ has not been visited, mark $v$ as visited and enqueue $v$.
   * **Depth-First Search (DFS):**
     * Employs a Last-In, First-Out (LIFO) **Stack** (or programmatic recursion).
     * Push the starting vertex into the stack and mark it as visited.
     * While the stack is non-empty: Pop vertex $u$; iterate across all unvisited adjacent vertices $v \in Adj[u]$; push unvisited vertices onto the stack and record them as visited.

### IV. Transitive Closure & Warshall’s Algorithm

#### Overview & Theoretical Foundation
Transitive closure determines global reachability within a directed graph across arbitrary path lengths. Rather than computing numeric shortest-path weights (as in the general Floyd-Warshall formulation), Warshall's algorithm constructs an unweighted boolean reachability matrix $T$. In this matrix, $T[i][j] = 1$ indicates that a directed path exists from vertex $i$ to vertex $j$ either through a direct edge or via one or more intermediate vertices; otherwise, $T[i][j] = 0$. Self-reachability is reflexive, meaning $T[i][i] = 1$ for all vertices.

#### Mechanics & Operational Invariants
1. **Initialization:**
   * Initialize a matrix $T$ of dimensions $n \times n$.
   * For every directed edge $(u, v) \in E$, set $T[u][v] = 1$.
   * Set $T[i][i] = 1$ for all $i \in V$ (reflexive invariant).
   * Set all other non-adjacent pairs to $0$.
2. **Iterative Dynamic Programming Update:**
   * Evaluate each vertex $k \in \{1, 2, \dots, n\}$ systematically as an allowed intermediate candidate.
   * For every cell $(i, j)$ in the matrix, update reachability using the boolean recurrence:
     $$T[i][j] = T[i][j] \lor (T[i][k] \land T[k][j])$$
   * If $T[i][j]$ is already $1$, the direct path remains satisfied.
   * If $T[i][j]$ is $0$, reachability is established if vertex $i$ can reach intermediate vertex $k$ ($T[i][k] == 1$) AND intermediate vertex $k$ can simultaneously reach vertex $j$ ($T[k][j] == 1$).

```
Warshall's Intermediate Reachability Step:
Vertex (i) ─── Direct edge absent? Check: ───> Intermediate (k) ───> Vertex (j)
If T[i][k] == 1 AND T[k][j] == 1  ===> Update T[i][j] = 1
```

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Time Complexity** | $\Theta(n^3)$ | The algorithm evaluates three nested loops: an outer loop iterating through intermediate vertices $k$ from $1$ to $n$, and two inner loops iterating through matrix rows $i$ and columns $j$ from $1$ to $n$. Total iterations equal $n \times n \times n = n^3$. |
| **Space Complexity** | $\Theta(n^2)$ | Auxiliary memory required to store the $n \times n$ boolean reachability matrix $T$. |

#### Design Trade-offs & Limitations
Warshall’s algorithm establishes complete all-pairs connectivity in dense matrix format without requiring separate graph traversal searches from each individual source vertex. However, for large sparse graphs, its rigid $\Theta(n^3)$ time and $\Theta(n^2)$ spatial footprints can become computationally expensive compared to executing targeted traversals.

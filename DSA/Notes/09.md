## 3. Key Concepts & Formal Definitions

| Concept / Term | Formal Definition & Operational Meaning | Contextual Constraints / Properties |
| :--- | :--- | :--- |
| **Tree (in Graph Theory)** | A connected, acyclic graph. | Must have no cycles and no disconnected vertices. |
| **Adjacent Vertices** | Vertices that share a direct edge connection. | Based solely on immediate, 1-hop connections. |
| **Degree of Vertex** | The total number of edges connected to a specific vertex. | Defines node connectivity density. |
| **Pendant / Leaf Vertex** | A vertex that has exactly a degree of one. | Represents a terminal endpoint in a network. |
| **Isolated Vertex** | A vertex with a degree of zero. | Unconnected to any part of the graph structure. |
| **Simple Graph** | A graph completely free of self-loops and parallel edges. | Standard representation for basic road networks or symmetric relationships. |
| **Pseudograph** | A graph that permits self-loops (edges connecting a node to itself). | Used in state machines or finite automata. |
| **Multigraph** | A graph that permits multiple parallel edges between the same pair of vertices. | Common in airline routing or multi-lane transit networks. |
| **Bipartite Graph** | A graph whose vertices can be divided into two independent sets ($V_1$, $V_2$) such that no edge connects vertices within the same set. | E.g., Matching students to courses. |
| **Complete Graph** | A simple undirected graph where every vertex is directly connected to every other vertex. | A graph with $n$ vertices contains $\frac{n(n-1)}{2}$ edges. |

## 4. Detailed Structured Technical Lecture Notes

### I. Expression Trees and Traversals

#### Overview & Theoretical Foundation
An expression tree is a binary tree used to represent algebraic expressions. The tree structure perfectly maps infix expressions to their prefix and postfix counterparts through standard tree traversals. The main algebraic operator acts as the root, with operands forming the left and right subtrees. 

#### Mechanics & Operational Invariants
1. **Tree Construction:** Identify the lowest-precedence main operator in the infix expression to serve as the root. Split the expression into left and right sub-expressions and recursively apply them as subtrees.
2. **Deriving Notations:** 
   * **In-order Traversal** yields the standard infix expression.
   * **Pre-order Traversal** yields the prefix expression.
   * **Post-order Traversal** yields the postfix expression.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Best-Case Time** | $\Omega(n)$ | Traversing the tree requires visiting every node exactly once. |
| **Worst-Case Time** | $O(n)$ | Direct derivation of the prefix/postfix sequence scales linearly with the number of operators and operands $n$. |

#### Design Trade-offs & Limitations
Expression trees strip away the need for parentheses. Postfix and prefix notations generated from these trees allow dumb computers to unambiguously evaluate complex algebraic operations without complex precedence rules.

### II. The Heap Data Structure

#### Overview & Theoretical Foundation
A heap is a specialized complete binary tree that maintains a strict hierarchical property. In a Max Heap, every parent node must be greater than or equal to its children, ensuring the absolute maximum value is always at the root. A Min Heap inverses this, ensuring the parent is always smaller than or equal to its children.

#### Mechanics & Operational Invariants
1. **Insertion:** 
   * Check if the tree is full.
   * Determine the insertion path by taking the total node count $N+1$ and converting it to binary. Ignoring the Most Significant Bit (MSB), traverse the tree from the root using the remaining bits ($0 \rightarrow$ Left, $1 \rightarrow$ Right).
   * Place the new node at the calculated end position.
   * **Upward Heapify:** Compare the newly inserted node with its parent. If the Max Heap property is violated, exchange them. Repeat this upward traversal until the property is satisfied or the root is reached.
2. **Deletion (Root Node):**
   * Check if the tree is empty.
   * Swap the root node (maximum element) with the absolute last node in the tree.
   * Decrement the total node count $N$.
   * **Downward Heapify:** Starting from the new root, compare the node with its left and right children. Swap it with the largest child. Repeat this downward process until the node is larger than both children or it becomes a leaf.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Best-Case Time** | $\Omega(1)$ | During heapify, if the node is already in the correct structural position, zero exchanges are required. |
| **Worst-Case Time** | $O(\log n)$ | In the worst case, a node must be exchanged from the leaf to the root (or vice versa). Since a heap is a complete binary tree, its height is strictly logarithmic. |

#### Design Trade-offs & Limitations
Heaps provide exceptional efficiency for accessing the maximum or minimum element immediately (in $O(1)$ time). However, searching for a specific arbitrary element inside the heap is inefficient, as the lack of a strict left/right total order requires falling back to standard tree traversal.

### III. Heap Sort & Priority Queues

#### Overview & Theoretical Foundation
Heap Sort leverages the invariant property of a Max Heap (or Min Heap) to sort an array. Because the root of a Max Heap always contains the largest unsorted element, continuously deleting the root yields elements in descending order.

#### Mechanics & Operational Invariants
1. **Step-by-Step Procedure:**
   * Build a Max Heap from the dataset.
   * Swap the root element with the last element in the heap.
   * Logically reduce the size of the heap by 1 (ignoring the swapped maximum value).
   * Trigger a downward `heapify` on the new root to restore the Max Heap property.
   * Repeat this extraction $N$ times until the heap is empty.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Worst-Case Time** | $O(n \log n)$ | Each root deletion requires a downward heapify operation taking $O(\log n)$ time. This is executed $N$ times. |

#### Design Trade-offs & Limitations
Heap sort provides consistent $O(n \log n)$ performance without requiring additional memory space (unlike Merge Sort). The same mechanics power Priority Queues, where processes are enqueued into a heap and dequeued strictly by their priority weight (the root).

### IV. Graph Traversals: Routes and Search Algorithms

#### Overview & Theoretical Foundation
Graphs can be navigated in varying ways depending on the constraints of edge and vertex repetition. Standardized search algorithms exist to systematically visit all reachable vertices in a graph.

#### Mechanics & Operational Invariants
1. **Route Constraints:**
   * **Walk:** A general sequence of connected vertices and edges.
   * **Trail:** A walk where no *edges* are repeated.
   * **Path:** A trail where no *vertices* are repeated.
   * **Closed Walk:** A walk that starts and ends at the exact same vertex.
   * **Circuit:** A closed trail.
   * **Cycle:** A closed path (excluding the start/end vertex repetition).
2. **Search Algorithms:**
   * **Breadth-First Search (BFS):** Utilizes a Queue (FIFO). Enqueue the starting vertex. Dequeue the vertex, mark it visited, and enqueue all unvisited adjacent vertices. Repeat until the queue is empty.
   * **Depth-First Search (DFS):** Utilizes a Stack (LIFO). Push the starting vertex. Pop the vertex, mark it visited, and push all unvisited adjacent vertices to the top of the stack. Repeat until the stack is empty.

#### Design Trade-offs & Limitations
BFS explores graphs layer-by-layer, making it ideal for finding the shortest path in unweighted graphs. DFS explores graphs deeply before backtracking, requiring less memory for broad trees but potentially diving infinitely in cyclic structures if visited nodes aren't properly tracked.

### V. Reachability & Transitive Closure

#### Overview & Theoretical Foundation
Transitive closure identifies absolute reachability within a directed graph. Instead of computing exact shortest distances, it creates a matrix determining if a path exists from vertex $i$ to vertex $j$, either directly or via indirect intermediaries.

#### Mechanics & Operational Invariants
1. **Step-by-Step Procedure (Floyd-Warshall Approach):**
   * Initialize a reachability matrix where direct edges are marked as $1$ and disconnected edges as $0$. (A node reaching itself is inherently $1$).
   * Iterate through every vertex acting as an intermediary $K$.
   * For every pair of vertices $i$ and $j$, update their reachability based on the intermediary:
     $$T[i][j] = T[i][j] \lor (T[i][k] \land T[k][j])$$
   * If a path exists from $i$ to $k$ and from $k$ to $j$, then a valid path exists from $i$ to $j$. 

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Worst-Case Time** | $O(n^3)$ | The algorithm evaluates every $(i, j)$ pair against every possible intermediate node $k$. This requires three nested loops, each scaling with the number of vertices $n$. |

#### Design Trade-offs & Limitations
The algorithm provides a complete mapping of network connectivity, resolving strongly connected and weakly connected component limits. However, the cubic time complexity $O(n^3)$ makes it computationally heavy and impractical for massive, dense graphs.

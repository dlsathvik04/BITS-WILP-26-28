## 3. Key Concepts & Formal Definitions

| Concept / Term | Formal Definition & Operational Meaning | Contextual Constraints / Properties |
| :--- | :--- | :--- |
| **Pre-Order Traversal** | A traversal where the root/parent node is visited prior to recursively visiting the left and right subtrees (Sequence: Root $\to$ Left $\to$ Right). | Operates in $O(n)$ time; the first output element represents the overall tree root. |
| **In-Order Traversal** | A traversal where the left subtree is recursively explored first, followed by the root/parent node, and finally the right subtree (Sequence: Left $\to$ Root $\to$ Right). | When evaluated over a valid Binary Search Tree, it outputs node keys in sorted ascending order. |
| **Post-Order Traversal** | A traversal where both left and right subtrees are visited before the root/parent node is recorded (Sequence: Left $\to$ Right $\to$ Root). | Operates in $O(n)$ time; the final output element represents the overall tree root. |
| **Level-Order Traversal** | A breadth-first traversal visiting nodes level by level from top to bottom and from left to right within each level. | Evaluated iteratively utilizing a FIFO Queue; matches sequential array order in standard array storage. |
| **Binary Search Tree (BST)** | A binary tree where each node possesses a key such that all keys in the left subtree are strictly less than the node key, and all keys in the right subtree are strictly greater. | Traversal via In-order yields monotonic ordering; finding min/max takes $O(h)$ where $h$ is tree height. |
| **Complete Binary Tree** | A binary tree in which every level is completely filled except possibly the last level, which is filled sequentially from left to right. | Provides a dense array representation without gaps; guarantees height $h = \lfloor \log_2 n \rfloor$. |
| **Full Binary Tree** | A binary tree in which every node other than the leaves possesses exactly two children. | Serves as an invariant condition allowing unique tree reconstruction using Pre-order and Post-order alone. |
| **Max-Heap Property** | The structural and ordering invariant where for every node $v$, its key is greater than or equal to the keys of its children: $\text{key}(v) \ge \text{key}(\text{left}(v))$ and $\text{key}(v) \ge \text{key}(\text{right}(v))$. | The maximum key within any subtree resides at the root of that subtree; overall maximum is at index 1 (or 0). |
| **Min-Heap Property** | The structural and ordering invariant where for every node $v$, its key is less than or equal to the keys of its children: $\text{key}(v) \le \text{key}(\text{left}(v))$ and $\text{key}(v) \le \text{key}(\text{right}(v))$. | The global minimum key resides strictly at the root node. |
| **Percolate Up (Sift-Up)** | Restorative operation after inserting a node at the leaf level: iteratively swapping the node with its parent while the heap-order property is violated. | Traverses a single path from leaf toward the root; bounded by height $O(\log n)$. |
| **Percolate Down (Heapify)** | Restorative operation after placing the last array element into the root: iteratively swapping the node with its larger (or smaller) child until order is restored. | Traverses down a single path of the tree; bounded by height $O(\log n)$. |

## 4. Detailed Structured Technical Lecture Notes

### I. Binary Tree Traversal Mechanics & Storage Mappings

#### Overview & Theoretical Foundation
Tree traversals define systematic visit orders for processing every vertex within a tree data structure exactly once. In standard sequential binary tree processing, traversals are classified based on the relative position of parent inspection against its child subtrees. Array-based representation of complete binary trees enables implicit parent-child navigation via index arithmetic without explicit pointer fields. The relationship between parent and child coordinates depends strictly on whether array indexing begins at zero or one.

#### Mechanics & Operational Invariants
1. **Mathematical Index Mappings:**
   * **Zero-Based Indexing ($0 \le i < n$):**
     * Root resides at index $0$.
     * For any parent node at index $i$:
       * $\text{Left Child Index} = 2i + 1$
       * $\text{Right Child Index} = 2i + 2$
       * $\text{Parent Index} = \lfloor \frac{i - 1}{2} \rfloor$
   * **One-Based Indexing ($1 \le i \le n$):**
     * Root resides at index $1$.
     * For any parent node at index $i$:
       * $\text{Left Child Index} = 2i$
       * $\text{Right Child Index} = 2i + 1$
       * $\text{Parent Index} = \lfloor \frac{i}{2} \rfloor$
2. **Recursive Traversal Execution Logic:**
   * `PreOrder(A, i, n)`: Validate boundary $(i \ge n \lor A[i] == \text{null})$; visit $A[i]$; recursively call `PreOrder(A, 2i+1, n)`; call `PreOrder(A, 2i+2, n)`.
   * `InOrder(A, i, n)`: Validate boundary; call `InOrder(A, 2i+1, n)`; visit $A[i]$; call `InOrder(A, 2i+2, n)`.
   * `PostOrder(A, i, n)`: Validate boundary; call `PostOrder(A, 2i+1, n)`; call `PostOrder(A, 2i+2, n)`; visit $A[i]$.
3. **Iterative Stack & Queue Implementations:**
   * *Stack-Based (Pre-order, In-order, Post-order):* Eliminates call stack recursion overhead. For Pre-order, the root is recorded, pushed, and as left branches terminate, nodes pop from the stack to route through right subtrees.
   * *Queue-Based (Level-order):* Uses a FIFO queue. Initialize queue with root; while queue is non-empty, dequeue node $u$, record $u$, and sequentially enqueue non-null left and right child pointers.
4. **Step-by-Step Traversal Walkthrough on Sample Tree:**
   Given a 7-node complete binary tree stored in array $A[0 \dots 6]$ with elements $A = [A, B, C, D, E, F, G]$:
   * Node mapping: $A$ (index 0, root); $B$ (index 1, left child of $A$); $C$ (index 2, right child of $A$); $D$ (index 3, left child of $B$); $E$ (index 4, right child of $B$); $F$ (index 5, left child of $C$); $G$ (index 6, right child of $C$).
   * *Pre-order Sequence:* $A \to B \to D \to E \to C \to F \to G$
   * *In-order Sequence:* $D \to B \to E \to A \to F \to C \to G$
   * *Post-order Sequence:* $D \to E \to B \to F \to G \to C \to A$ (Note: Returning from $D$ and $E$ records parent $B$, before visiting $C$'s children $F, G$, then parent $C$, ending at root $A$).
   * *Level-order Sequence:* $A \to B \to C \to D \to E \to F \to G$

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Time Complexity (All Traversals)** | $\Theta(n)$ | Every node of the $n$-element tree is enqueued/pushed and visited exactly once. |
| **Space Complexity (Recursive Call Stack)** | $O(h)$ | Proportional to tree height $h$; ranges from $O(\log n)$ for balanced trees to $O(n)$ in degenerate trees. |
| **Space Complexity (Iterative Level-Order)** | $O(w)$ | Governed by maximum tree width $w$; for a full binary tree, maximum queue size is $\lceil n / 2 \rceil = O(n)$. |

#### Design Trade-offs & Limitations
Array implementations maximize cache locality and avoid pointer overhead for complete binary trees. However, for sparse or unbalanced binary trees, index calculations like $2i+1$ lead to vast empty array slots, necessitating linked-list representations where memory is allocated dynamically per node at the cost of reference overhead.

### II. Binary Search Trees & Tree Reconstruction

#### Overview & Theoretical Foundation
A Binary Search Tree enforces an explicit ordering constraint across all subtrees. For any arbitrary node $x$, all keys residing in the left subtree of $x$ satisfy $\text{Key}(\text{left}) < \text{Key}(x)$, and all keys residing in the right subtree satisfy $\text{Key}(\text{right}) > \text{Key}(x)$. A fundamental consequence of this invariant is that an In-order traversal across any valid BST processes elements in strictly ascending, sorted order. Furthermore, traversal sequences can uniquely reconstruct a binary tree topology under specific structural criteria.

#### Mechanics & Operational Invariants
1. **In-Order Sorting Invariant:**
   * Given traversal sequence $D, B, E, A, F, C, G$ on a valid BST:
     $$\text{Key}(D) < \text{Key}(B) < \text{Key}(E) < \text{Key}(A) < \text{Key}(F) < \text{Key}(C) < \text{Key}(G)$$
   * Minimum element resides at the leftmost node ($\text{Key}(D)$); maximum element resides at the rightmost node ($\text{Key}(G)$).
2. **Reconstruction from Pre-Order and In-Order:**
   * *Step 1:* Identify the global root as the first element of the Pre-order sequence.
   * *Step 2:* Locate this root element within the In-order sequence.
   * *Step 3:* Elements to the left of the root in the In-order sequence form the Left Subtree; elements to the right form the Right Subtree.
   * *Step 4:* Count the number of left-subtree elements ($k$) from the In-order split. The next $k$ elements in the Pre-order sequence correspond to the Left Subtree, and the subsequent elements belong to the Right Subtree.
   * *Step 5:* Recursively repeat the sub-routine for both partitions.
   * *Worked Example:*
     * Given Pre-order: `[11, 9, 8, 10, 13, 12, 14]`
     * Given In-order: `[8, 9, 10, 11, 12, 13, 14]`
     * Root $= 11$.
     * In-order split: Left subtree contains $\{8, 9, 10\}$; Right subtree contains $\{12, 13, 14\}$.
     * In left partition, next Pre-order element is $9$ (root of left subtree). In-order split around $9$ sets $8$ as left child and $10$ as right child.
     * In right partition, next Pre-order element is $13$ (root of right subtree). In-order split around $13$ sets $12$ as left child and $14$ as right child.
3. **Reconstruction from Post-Order and In-Order:**
   * Follows symmetrical logic: the root is identified from the *last* element of the Post-order sequence.
   * Locate root in In-order to determine left/right partition sizes.
   * The second-to-last element in Post-order represents the root of the Right Subtree.
4. **Reconstruction from Pre-Order and Post-Order (Full Binary Tree Assumption):**
   * Pre-order first element is root; Post-order last element is root.
   * The second element of Pre-order defines the root of the Left Subtree.
   * Locate this left-subtree root in the Post-order sequence: all elements up to and including this value constitute the left subtree. Remaining elements before the global root constitute the right subtree.
   * *Limitation:* Without the assumption that every node has either 0 or 2 children (Full Binary Tree), Pre-order and Post-order cannot differentiate whether a single child is a left or right branch, producing ambiguous topologies.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Search Min/Max in General Binary Tree** | $O(n)$ | Unordered nodes require complete level-order or recursive search across all vertices. |
| **Search Min/Max in Balanced BST** | $O(h) = O(\log n)$ | Follow left-most or right-most pointer directly down tree depth. |
| **Unique Reconstruction Time** | $O(n^2)$ naive / $O(n)$ | Linear scan to search root index in In-order sequence per recursion step ($O(n \log n)$ to $O(n)$ with hash mapping). |

#### Design Trade-offs & Limitations
A combination of Pre-order and In-order or Post-order and In-order uniquely produces an arbitrary binary tree. However, Pre-order paired with Post-order inherently lacks orientation markers for internal nodes with degree 1. It strictly requires the Full Binary Tree property to avoid topological ambiguity.

### III. Binary Heap Structures & Priority Queues

#### Overview & Theoretical Foundation
A Binary Heap is a complete binary tree that maintains the Heap-Order Property, optimized for Priority Queue implementations. Unlike Binary Search Trees where ordering distinguishes left from right children, heap ordering governs parent-to-child relationships globally across subtrees. Heaps provide immediate $O(1)$ accessibility to the extreme element (maximum in a Max-Heap, minimum in a Min-Heap) while guaranteeing a minimal structural tree height of $\lfloor \log_2 n \rfloor$ through completeness.

#### Mechanics & Operational Invariants
1. **Core Structural & Order Invariants:**
   * *Completeness:* All levels are fully packed, except possibly the final level which is packed from left to right.
   * *Max-Heap Invariant:* For any node $v$ having parent $p$:
     $$\text{Key}(p) \ge \text{Key}(v)$$
     The overall maximum key resides at the root $A[1]$ (or $A[0]$).
   * *Min-Heap Invariant:* For any node $v$ having parent $p$:
     $$\text{Key}(p) \le \text{Key}(v)$$
     The overall minimum key resides at the root $A[1]$ (or $A[0]$).
2. **Linked-List Heap Representation via Binary Coordinate Routing:**
   * When implementing heaps via explicit pointers instead of arrays, index arithmetic ($\lfloor i / 2 \rfloor$) is unavailable.
   * *Bitwise Path Resolution:* To locate the parent and path for node insertion at position $n$:
     * Express $n$ in standard binary notation.
     * Strip off the most significant bit (MSB), which represents the root.
     * Read remaining bits from left to right: bit `0` directs branch traversal to `Left Child`; bit `1` directs branch traversal to `Right Child`.
     * The prefix ending one bit before the final bit identifies the target parent pointer directly.
   * *Example:* For position $n = 9$ (binary `1001`):
     * Ignore MSB (`1`). Remaining bits: `001`.
     * Path: Go Left (`0`) $\to$ Go Left (`0`) $\to$ Go Right (`1`).
     * Node 9 is the right child of node 4 (`100`).

```
          [Root: 1]
         /         \
     [2: 10]      [3: 11]
     /     \
  [4: 100] [5: 101]
  /     \
[8]     [9: 1001]
```

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Find Max / Min** | $\Theta(1)$ | Stored immutably at the root index ($A[1]$ or $A[0]$). |
| **Height Bound** | $\Theta(\log n)$ | Guaranteed due to complete binary tree structural packing. |

#### Design Trade-offs & Limitations
Heaps allow $O(1)$ lookup for the extremum element, significantly faster than unsorted arrays ($O(n)$). However, arbitrary searching of non-root keys in a heap requires $O(n)$ time, lacking the directional search capabilities of Binary Search Trees ($O(\log n)$).

### IV. Heap Dynamic Operations & Maintenance (Insert, Delete, Heapify)

#### Overview & Theoretical Foundation
Dynamic operations on heaps modify either tree topology or node values, momentarily violating the structural or ordering invariants. To restore stability, restorative procedures—sift-up (percolate up) and sift-down (percolate down / heapify)—reposition out-of-place keys along vertical branch paths without corrupting unrelated subtrees.

#### Mechanics & Operational Invariants
1. **Insertion via Percolate-Up (Sift-Up):**
   * *Procedure:*
     1. Verify capacity: if $n \ge \text{size}$, trigger overflow error.
     2. Increment $n \leftarrow n + 1$.
     3. Insert incoming element $X$ into the next available complete binary tree position at index $n$.
     4. Set current pointer index $i = n$. Compute parent index $j = \lfloor i / 2 \rfloor$ (under 1-based indexing).
     5. While $j > 0$ and $A[j] < A[i]$ (for Max-Heap):
        * Swap values $A[j] \leftrightarrow A[i]$.
        * Shift upward: $i \leftarrow j$, $j \leftarrow \lfloor i / 2 \rfloor$.
   * *Trace Example:* Insert key `101` into a Max-Heap where index 4 holds value `10`, parent at index 2 holds `40`, root at index 1 holds `100`.
     * Position `101` at index 8 (child of index 4).
     * Compare $101 > 10 \implies$ Swap (`101` moves to index 4, `10` descends).
     * Compare $101 > 40 \implies$ Swap (`101` moves to index 2, `40` descends).
     * Compare $101 > 100 \implies$ Swap (`101` moves to index 1, `100` descends).
     * Termination: `101` becomes global root; other subtrees remain intact.
2. **Deletion of Extremum via Percolate-Down:**
   * In a heap, deletion is fundamentally restricted to removing the root element.
   * *Procedure:*
     1. Verify underflow: if $n == 0$, return empty.
     2. Extract $A[1]$ as return output.
     3. Move the final element in the complete binary tree $A[n]$ into the root position $A[1]$.
     4. Decrement size $n \leftarrow n - 1$.
     5. Set $i = 1$, $\text{flag} = \text{false}$.
     6. While $\text{flag} == \text{false}$ and $2i \le n$:
        * Left child index $= 2i$, Right child index $= 2i + 1$.
        * Identify the larger child: $\text{max\_child} = \text{argmax}(A[2i], A[2i+1])$.
        * If $A[i] < A[\text{max\_child}]$:
          * Swap $A[i] \leftrightarrow A[\text{max\_child}]$.
          * Update $i \leftarrow \text{max\_child}$.
        * Else:
          * Set $\text{flag} = \text{true}$ (heap invariant restored; terminate).
3. **The Heapify Concept (Sift-Down at Arbitrary Nodes):**
   * Operates on an out-of-order element placed at index $i$ whose left and right subtrees are already valid heaps.
   * Recursively or iteratively sinks the key down along the maximum-child trajectory until it dominates both child subtrees.
4. **Linear Build-Heap Construction ($\Theta(n)$ Analysis):**
   * *Naive Construction:* Repeated insertion of $n$ elements sequentially into an initially empty heap requires:
     $$\sum_{i=1}^n O(\log i) = O(n \log n)$$
   * *Bottom-Up Floyd Construction:* Populate an array with all $n$ arbitrary elements without regard to order (satisfying completeness).
   * Apply `Heapify` in reverse level order starting from the last non-leaf parent node down to the root:
     $$\text{Starting index} = \left\lfloor \frac{n}{2} \right\rfloor \quad \text{down to } 1$$
   * Nodes at height $0$ (leaves, numbering $\lceil n / 2 \rceil$) require $0$ swaps.
   * Nodes at height $1$ (numbering $\approx n / 4$) require at most $1$ swap.
   * Nodes at height $2$ (numbering $\approx n / 8$) require at most $2$ swaps.
   * Total work $S$ across all heights $h$:
     $$S = \sum_{h=0}^{\lfloor \log n \rfloor} \left( \frac{n}{2^{h+1}} \right) \cdot O(h) = \frac{n}{2} \sum_{h=0}^{\lfloor \log n \rfloor} \frac{h}{2^h} = O(n)$$
   * The summation converges to a constant factor, yielding a linear $\Theta(n)$ build-heap runtime.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Insert Single Element** | $O(\log n)$ | Single sift-up path traversal bounded by tree height $h = \log_2 n$. |
| **Delete Root Element** | $O(\log n)$ | Single sift-down path traversal bounded by tree height $h = \log_2 n$. |
| **Heapify Function (Single Node)** | $O(\log n)$ | Sifts down through child nodes along one branch path to leaf level. |
| **Build-Heap (Bottom-Up from Scratch)** | $\Theta(n)$ | Convergent series: majority of nodes reside near leaf level requiring minimal downward sift distance. |
| **Auxiliary Space Complexity** | $O(1)$ | In-place swaps performed directly within the array bounds. |

#### Design Trade-offs & Limitations
Building a heap bottom-up via backwards-indexed heapify is asymptotically superior ($\Theta(n)$) compared to sequential element insertion ($O(n \log n)$). However, deletion is strictly constrained to the root priority element; arbitrary key deletion or key lookup requires linear scans unless supplemented with secondary index-tracking map structures.

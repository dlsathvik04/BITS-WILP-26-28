## 1. Core Topics For Self Study

To establish a solid foundation for **Data Structures and Algorithm Design**, students should focus self-study on the following core topic areas introduced in the course handout:

1. **Foundations of Algorithm Analysis**
   - RAM (Random Access Machine) model of computation.
   - Time and space complexity metrics; best-case, average-case, and worst-case analysis.
   - Asymptotic notation ($\mathcal{O}, \Omega, \Theta$) and growth of functions.
   - Correctness proofs for iterative and recursive algorithms (loop invariants, mathematical induction).

2. **Recurrences and Mathematical Tools**
   - Setting up recurrence relations for recursive/divide-and-conquer algorithms.
   - Methods for solving recurrences: Substitution method, Recursion Tree method, and the Master Theorem.

3. **Linear & Non-Linear Data Structures**
   - Abstract Data Types (ADTs): Stacks, Queues, Linked Lists.
   - Trees and Hierarchical Data Structures: Binary Trees, Binary Search Trees (BST), Heaps, and Priority Queues.
   - Height-balanced trees: AVL Trees, Red-Black Trees, $k$-d Trees.

4. **Dictionary Data Structures & Hashing**
   - Hash tables, hash functions, collision resolution strategies (chaining, open addressing).
   - Universal hashing and consistent performance bounds.

5. **Algorithm Design Paradigms**
   - Divide and Conquer strategy.
   - Greedy Algorithms and optimal substructure.
   - Dynamic Programming (memoization vs. tabulation).

6. **Advanced Topics: Complexity Classes & Approximation**
   - Graph representation and traversal algorithms (BFS, DFS, shortest paths, MST).
   - Complexity classes: $\mathcal{P}$, $\mathcal{NP}$, $\mathcal{NP}$-Hard, and $\mathcal{NP}$-Complete.
   - Approximation algorithms for computationally intractable problems.

## 2. Key Concepts & Definitions

| Term / Framework | Definition & Description |
| :--- | :--- |
| **RAM Model** | **Random Access Machine Model:** An abstract computational framework assuming uniform execution time (constant time $\mathcal{O}(1)$) for basic arithmetic, logical, and memory access operations. |
| **Asymptotic Analysis** | Mathematical evaluation of algorithm execution efficiency as the input size $n$ approaches infinity ($\to \infty$). |
| **Big-$\mathcal{O}$ ($\mathcal{O}$)** | Asymptotic upper bound defining the maximum growth rate of an algorithm's execution time or memory usage. |
| **Big-$\Omega$ ($\Omega$)** | Asymptotic lower bound defining the minimum performance threshold of an algorithm. |
| **Big-$\Theta$ ($\Theta$)** | Asymptotic tight bound holding both upper and lower bounds ($\mathcal{O}$ and $\Omega$) simultaneously. |
| **Master Theorem** | A standardized algebraic formula for solving divide-and-conquer recurrences of the form $T(n) = a T(n/b) + f(n)$. |
| **Abstract Data Type (ADT)** | A high-level mathematical model for data structures specifying operational behavior independent of specific programming language implementations. |
| **Height-Balanced Tree** | A binary search tree variant (e.g., AVL tree) that enforces structural constraints on node heights to guarantee logarithmic search, insertion, and deletion operations ($\mathcal{O}(\log n)$). |
| **Universal Hashing** | Randomized selection of a hash function from a carefully designed family of functions to minimize collision probability to $\le 1/m$. |
| **Class $\mathcal{P}$** | The set of decision problems solvable by a deterministic Turing machine in polynomial time ($\mathcal{O}(n^k)$). |
| **Class $\mathcal{NP}$** | The set of decision problems whose proposed solutions can be verified by a deterministic machine in polynomial time. |
| **$\mathcal{NP}$-Hard / $\mathcal{NP}$-Complete** | Problems at least as hard as the hardest problems in $\mathcal{NP}$. $\mathcal{NP}$-Complete problems belong to $\mathcal{NP}$ and are $\mathcal{NP}$-Hard. |
| **Approximation Algorithm** | An efficient polynomial-time algorithm designed to find near-optimal solutions (guaranteed within a bounded factor $\alpha$) for $\mathcal{NP}$-Hard optimization problems. |

#### Module 1: Analyzing Algorithms
- Introduction to computational problem-solving and algorithm specification.

- Algorithmic correctness proofs via loop invariants.
- Analyzing recursive algorithms using recurrence equations:
  - Substitution Method
  - Recursion Tree Method
  - Master Theorem

#### Module 2: Linear Data Structures
- Specification and implementation of Linear Abstract Data Types (ADTs).
- **Stack:** Operations (`push`, `pop`, `peek`), array and linked implementations, applications (expression evaluation, function call management).
- **Queue:** Operations (`enqueue`, `dequeue`), circular queues, double-ended queues (Deques).

#### Module 3: Non-Linear Data Structures & Graph Structures
- Hierarchical structures: Trees, Binary Search Trees (BST), Traversals (Pre-order, In-order, Post-order, Level-order).

#### Module 4: Dictionary Data Structures
- Search Trees: Height-balanced trees (AVL Trees, Red-Black Trees).
- Spatial Data Structures: $k$-d Trees.
- Hash Tables: Direct addressing, Hash functions, Collision resolution (Chaining, Linear/Quadratic Probing, Double Hashing), Universal Hashing.

#### Module 5: Algorithm Design Techniques
- **Divide and Conquer:** Paradigm, recurrence relations, applications (Merge Sort, Quick Sort).
- **Greedy Strategy:** Greedy-choice property, optimal substructure, applications (Fractional Knapsack, Huffman coding).
- **Dynamic Programming:** Overlapping subproblems, optimal substructure, memoization vs. tabulation (0/1 Knapsack, Longest Common Subsequence).

#### Module 6: Complexity Classes & Approximation Algorithms
- Intractability: Deterministic vs. Non-deterministic computation.
- Classes $\mathcal{P}$, $\mathcal{NP}$, $\mathcal{NP}$-Hard, and $\mathcal{NP}$-Complete problems (3-SAT, Vertex Cover, TSP).
- Approximation Algorithms: Performance ratio, polynomial-time approximation schemes (PTAS) for intractable problems.

### Part B: Conceptual Short-Answer Problems

#### Problem 1: Master Theorem Application
Given the recursive recurrence relation:
$$T(n) = 4 T\left(\frac{n}{2}\right) + n$$

Use the Master Theorem to determine the tight asymptotic bound $\Theta(f(n))$ for $T(n)$.

**Solution:**
1. The standard Master Theorem form is $T(n) = a T(n/b) + f(n)$.
2. Here, $a = 4$, $b = 2$, and $f(n) = n$.
3. Compute $n^{\log_b a} = n^{\log_2 4} = n^2$.
4. Compare $f(n) = n$ with $n^{\log_b a} = n^2$:
   - $f(n) = \mathcal{O}\left(n^{\log_2 4 - \epsilon}\right) = \mathcal{O}(n^{2 - 1}) = \mathcal{O}(n)$ for $\epsilon = 1$.
5. This falls under **Case 1** of the Master Theorem.
6. **Conclusion:** $T(n) = \Theta\left(n^{\log_b a}\right) = \Theta(n^2)$.

#### Problem 2: Loop Invariant Correctness
Explain the three required properties of a **Loop Invariant** used to prove the mathematical correctness of an iterative algorithm.

**Solution:**
A loop invariant is a formal predicate that must hold true for every iteration of a loop. To prove correctness, three steps must be established:
1. **Initialization:** The invariant must be true prior to the first iteration of the loop.
2. **Maintenance:** If the invariant is true before an iteration of the loop, it remains true before the next iteration.
3. **Termination:** When the loop terminates, the invariant gives us a useful property that helps prove the algorithm is correct.

#### Problem 3: Greedy vs. Dynamic Programming Paradigms
Distinguish between the **Greedy Strategy** and **Dynamic Programming** in terms of optimal substructure and subproblem dependencies.

**Solution:**
- **Optimal Substructure:** Both paradigms require that an optimal solution to the problem contains optimal solutions to its subproblems.
- **Subproblem Overlap & Choice Mechanism:**
  - **Greedy Method:** Makes a locally optimal choice at each step without re-evaluating previous choices or examining solutions to subproblems. It requires the *greedy-choice property* and does not require overlapping subproblems.
  - **Dynamic Programming:** Applies when subproblems **overlap** (i.e., subproblems share sub-subproblems). DP evaluates all possible choices, solves each subproblem once, and stores the results to avoid redundant computation.

## 2. Key Concepts & Definitions

### Glossary of Terms & Frameworks

* **Algorithm Analysis**: The process of determining the computational resources (time and space complexity) required by an algorithm as a function of the input size $n$.
* **RAM (Random Access Machine) Model**: An abstract machine model assuming unit-time cost for basic operations (arithmetic, memory access) used to analyze algorithm efficiency independent of specific hardware.
* **Asymptotic Notation**: Mathematical notations ($\mathcal{O}, \Omega, \Theta$) used to classify algorithms according to their rate of growth:
  * **Big-O ($\mathcal{O}$)**: Asymptotic upper bound ($f(n) \le c \cdot g(n)$ for large $n$).
  * **Big-Omega ($\Omega$)**: Asymptotic lower bound ($f(n) \ge c \cdot g(n)$ for large $n$).
  * **Big-Theta ($\Theta$)**: Asymptotic tight bound ($c_1 \cdot g(n) \le f(n) \le c_2 \cdot g(n)$ for large $n$).
* **Recurrence Relation**: An equation that defines a sequence or algorithm running time recursively in terms of smaller input sizes (e.g., $T(n) = aT(n/b) + f(n)$).
* **Master Theorem**: A algorithmic technique providing a closed-form solution for divide-and-conquer recurrences of the form $T(n) = aT(n/b) + f(n)$.
* **Abstract Data Type (ADT)**: A mathematical model for data types defined by behavior (operations) rather than implementation.
* **Height-Balanced Trees (AVL Trees)**: A self-balancing binary search tree where the height difference (balance factor) between left and right subtrees of any node is at most 1.
* **kd-Tree ($k$-dimensional Tree)**: A space-partitioning data structure for organizing points in a $k$-dimensional space.
* **Universal Hashing**: Selecting a hash function at random from a family of hash functions with a guaranteed low probability of collisions.
* **Complexity Classes ($P, NP, NP\text{-Hard}, NP\text{-Complete}$)**:
  * **$P$**: Decision problems solvable in polynomial time.
  * **$NP$**: Decision problems verifiable in polynomial time.
  * **$NP\text{-Hard}$**: Problems at least as hard as the hardest problems in $NP$.
  * **$NP\text{-Complete}$**: Problems that are both in $NP$ and $NP\text{-Hard}$.
* **Approximation Algorithm**: An efficient algorithm that finds a near-optimal solution to an $NP$-Hard optimization problem with a proven performance guarantee (approximation ratio).

#### Module 1: Analyzing Algorithms & Theoretical Foundations
- Introduction to algorithms, necessity of formal analysis.
- **Random Access Machine (RAM)** model.
- Best-case, Average-case, and Worst-case execution analysis.
- Algorithm correctness proofs (loop invariants, mathematical induction).
- Asymptotic notations: $\mathcal{O}, \Omega, \Theta, o, \omega$.
- Solving recurrences: Substitution method, Recursion-tree method, Master Theorem.

#### Module 2: Linear Data Structures
- Abstract Data Types (ADTs).
- **Stack**: Operations (Push, Pop, Peek), array and linked-list implementations, applications (expression evaluation, function calls).
- **Queue**: Operations (Enqueue, Dequeue), circular queues, double-ended queues (Deques), priority queues.

#### Module 3: Non-Linear Data Structures & Graph Algorithms
- **Trees**: Terminology, binary trees, traversals (In-order, Pre-order, Post-order, Level-order).
- **Heaps**: Min-heap/Max-heap properties, heapify, insertion, deletion, HeapSort.
- **Graphs**: Representation (Adjacency Matrix, Adjacency List), traversals (BFS, DFS), Shortest Path algorithms, Minimum Spanning Trees (MST).

#### Module 4: Dictionary Data Structures & Search Trees
- **Hash Tables**: Hash functions, collision resolution strategies (Chaining, Open Addressing: Linear/Quadratic Probing, Double Hashing), Universal Hashing.
- **Search Trees**: Binary Search Trees (BST) operations and limitations.
- **Self-Balancing Trees**: AVL Trees (Rotations: LL, RR, LR, RL), height bounds.
- **Multi-Dimensional Search**: $k$-d Trees for spatial search queries.

#### Module 5: Algorithm Design Techniques
- **Greedy Algorithms**: Local choice optimization, Fractional Knapsack, Huffman Coding, Minimum Spanning Trees (Kruskal’s / Prim’s).
- **Divide and Conquer**: Decomposition, recursive solving, combining solutions (MergeSort, QuickSort).
- **Dynamic Programming**: Optimal substructure, overlapping subproblems, memoization vs. tabulation (0/1 Knapsack, Longest Common Subsequence).

#### Module 6: Complexity Classes & Approximation Algorithms
- Intractability: Decision vs. Optimization problems.
- Complexity classes $P$, $NP$, $NP$-Complete, $NP$-Hard.
- Reductions and proving $NP$-Completeness.
- **Approximation Algorithms**: Performance ratios, design of approximation heuristics for $NP$-Hard problems (e.g., Vertex Cover, Traveling Salesperson Problem).

### 6.2 Short-Answer & Conceptual Problems

#### Problem 1
**Differentiate between worst-case, best-case, and average-case analysis of algorithms. Why is worst-case analysis generally preferred in computer science?**

* **Sample Answer**:
  * **Worst-Case Analysis**: Measures the maximum time/space required by an algorithm over all inputs of size $n$. It provides a guaranteed upper bound on running time.
  * **Best-Case Analysis**: Measures the minimum time/space required for an input of size $n$ (often representing optimal/already-sorted conditions).
  * **Average-Case Analysis**: Computes the expected resource usage over a statistical distribution of all possible inputs of size $n$.
  * **Preference for Worst-Case**: Worst-case analysis provides a firm reliability guarantee—the algorithm will *never* take longer than this bound. Average-case analysis requires complex probabilistic assumptions about input distribution which may not reflect real-world scenarios.

---

#### Problem 2
**Explain the structural difference between dynamic programming and divide-and-conquer algorithm design techniques.**

* **Sample Answer**:
  * **Divide and Conquer**: Breaks a problem into independent subproblems, solves them recursively, and combines their results (e.g., MergeSort, QuickSort). Subproblems do not overlap.
  * **Dynamic Programming**: Applies when subproblems **overlap** and exhibit **optimal substructure**. Instead of solving identical subproblems repeatedly, dynamic programming solves each subproblem once and stores the result in a table (memoization or tabulation) to avoid redundant computation (e.g., 0/1 Knapsack, Floyd-Warshall).

---

#### Problem 3
**Describe the core problem addressed by Universal Hashing and state how it prevents worst-case performance degradation in Hash Tables.**

* **Sample Answer**:
  * **Problem**: In deterministic hashing, if an adversary knows the fixed hash function, they can deliberately feed a sequence of keys that all hash to the same slot, turning $\mathcal{O}(1)$ average-time operations into $\mathcal{O}(n)$ worst-case time (a single linked list).
  * **Universal Hashing Solution**: Universal hashing selects a hash function randomly at runtime from a carefully designed family $\mathcal{H}$ of hash functions. Because the function is chosen randomly, no adversary can predict collisions in advance, guaranteeing that the expected number of collisions for any given key is at most $1/m$ (where $m$ is table size), maintaining expected $\mathcal{O}(1)$ performance.

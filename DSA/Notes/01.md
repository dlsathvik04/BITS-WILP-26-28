## 2. Key Concepts & Definitions

| Term / Framework | Definition & Description |
| :--- | :--- |
| **RAM Model** | **Random Access Machine Model:** An abstract computational framework depicting the functionalities of a Turing machine, assuming uniform execution time (constant time $\mathcal{O}(1)$) for basic arithmetic, logical, and memory access operations[cite: 1, 2]. |
| **Asymptotic Analysis** | Mathematical evaluation of algorithm execution efficiency as the input size $n$ approaches infinity ($\to \infty$)[cite: 1, 2]. |
| **Big-$\mathcal{O}$ ($\mathcal{O}$)** | Asymptotic upper bound defining the maximum growth rate of an algorithm's execution time or memory usage[cite: 1, 2]. |
| **Big-$\Omega$ ($\Omega$)** | Asymptotic lower bound defining the minimum performance threshold of an algorithm[cite: 1, 2]. |
| **Big-$\Theta$ ($\Theta$)** | Asymptotic tight bound holding both upper and lower bounds ($\mathcal{O}$ and $\Omega$) simultaneously[cite: 1]. |
| **Master Theorem** | A standardized algebraic formula for solving divide-and-conquer recurrences of the form $T(n) = a T(n/b) + f(n)$ rapidly within minutes[cite: 1, 2]. |
| **Abstract Data Type (ADT)** | A high-level mathematical model for data structures specifying operational behavior independent of specific programming language implementations[cite: 1, 2]. |
| **Height-Balanced Tree** | A binary search tree variant (e.g., AVL tree) that enforces structural constraints on node heights to guarantee logarithmic search, insertion, and deletion operations ($\mathcal{O}(\log n)$)[cite: 1, 2]. |
| **Universal Hashing** | Randomized selection of a hash function from a carefully designed family of functions to minimize collision probability to $\le 1/m$[cite: 1, 2]. |
| **Class $\mathcal{P}$** | The set of decision problems solvable by a deterministic Turing machine in polynomial time ($\mathcal{O}(n^k)$)[cite: 1, 2]. |
| **Class $\mathcal{NP}$** | The set of decision problems whose proposed solutions can be verified by a deterministic machine in polynomial time[cite: 1, 2]. |
| **$\mathcal{NP}$-Hard / $\mathcal{NP}$-Complete** | Problems at least as hard as the hardest problems in $\mathcal{NP}$. For $\mathcal{NP}$-Hard problems, no polynomial-time exact solutions exist[cite: 1, 2]. |
| **Approximation Algorithm** | An efficient polynomial-time algorithm designed to find near-optimal, bounded solutions for $\mathcal{NP}$-Hard optimization problems where exact polynomial-time solutions are impossible[cite: 1, 2]. |

### Part B: Conceptual Short-Answer Problems

#### Problem 1: Master Theorem Application
Given the recursive recurrence relation:
$$T(n) = 4 T\left(\frac{n}{2}\right) + n$$

Use the Master Theorem to determine the tight asymptotic bound $\Theta(f(n))$ for $T(n)$[cite: 1].

**Solution:**
1. The standard Master Theorem form is $T(n) = a T(n/b) + f(n)$[cite: 1].
2. Here, $a = 4$, $b = 2$, and $f(n) = n$[cite: 1].
3. Compute $n^{\log_b a} = n^{\log_2 4} = n^2$[cite: 1].
4. Compare $f(n) = n$ with $n^{\log_b a} = n^2$:
   - $f(n) = \mathcal{O}\left(n^{\log_2 4 - \epsilon}\right) = \mathcal{O}(n^{2 - 1}) = \mathcal{O}(n)$ for $\epsilon = 1$[cite: 1].
5. This falls under **Case 1** of the Master Theorem[cite: 1].
6. **Conclusion:** $T(n) = \Theta\left(n^{\log_b a}\right) = \Theta(n^2)$[cite: 1].

#### Problem 2: Loop Invariant Correctness
Explain the three required properties of a **Loop Invariant** used to prove the mathematical correctness of an iterative algorithm[cite: 1].

**Solution:**
A loop invariant is a formal predicate that must hold true for every iteration of a loop[cite: 1]. To prove correctness, three steps must be established:
1. **Initialization:** The invariant must be true prior to the first iteration of the loop[cite: 1].
2. **Maintenance:** If the invariant is true before an iteration of the loop, it remains true before the next iteration[cite: 1].
3. **Termination:** When the loop terminates, the invariant gives us a useful property that helps prove the algorithm is correct[cite: 1].

#### Problem 3: Greedy vs. Dynamic Programming Paradigms
Distinguish between the **Greedy Strategy** and **Dynamic Programming** in terms of optimal substructure and subproblem dependencies[cite: 1].

**Solution:**
- **Optimal Substructure:** Both paradigms require that an optimal solution to the problem contains optimal solutions to its subproblems[cite: 1].
- **Subproblem Overlap & Choice Mechanism:**
  - **Greedy Method:** Makes a locally optimal choice at each step without re-evaluating previous choices or examining solutions to subproblems[cite: 1]. It requires the *greedy-choice property* and does not require overlapping subproblems[cite: 1].
  - **Dynamic Programming:** Applies when subproblems **overlap** (i.e., subproblems share sub-subproblems)[cite: 1]. DP evaluates all possible choices, solves each subproblem once, and stores the results to avoid redundant computation[cite: 1].

## 3. Key Concepts & Formal Definitions

| Concept / Term | Formal Definition & Operational Meaning | Contextual Constraints / Properties |
| :--- | :--- | :--- |
| **Linear Queue** | A First-In-First-Out (FIFO) linear data structure where elements are inserted at the rear and removed from the front. | Bounded by a fixed allocation size $\text{Max}$; suffers from memory wastage and false overflow upon repeated operations. |
| **False Overflow** | A condition where a linear queue denies further enqueue operations because $\text{rear} = \text{Max} - 1$, despite vacant slots existing at indices preceding $\text{front}$. | Occurs exclusively in statically sized array implementations of linear queues when $\text{front} > 0$. |
| **Circular Queue** | A FIFO linear structure where the storage array is logically circular, connecting the last position back to the first using modulo arithmetic. | Overcomes false overflow; full condition occurs when $(\text{rear} + 1) \pmod{\text{Max}} = \text{front}$. |
| **Double-Ended Queue (Deque)** | A linear data structure supporting insertion and deletion operations at both the front and rear endpoints. | Generalizes stacks and queues; requires bidirectional index updates using forward and backward modulo arithmetic. |
| **Priority Queue (PQ)** | An abstract data type where each element possesses an associated priority level, dictating the deletion order rather than the arrival timestamp. | Elements with identical priority default to FIFO processing; implemented as Min-PQ (lowest priority processed first) or Max-PQ (highest priority processed first). |
| **Amortized Complexity** | The average time per operation evaluated over a worst-case sequence of operations (e.g., resizing a dynamically expanding array). | Guarantees that expensive periodic maintenance operations ($O(n)$ copies) do not compromise long-term asymptotic efficiency ($O(1)$ amortized). |
| **Singly Linked List (SLL)** | A dynamic linear collection of discrete nodes, where each node encapsulates a data payload and a single pointer (`next`) to its successor. | Non-contiguous memory allocation; unidirectional traversal only; final node points to $\text{NULL}$. |
| **Doubly Linked List (DLL)** | A dynamic collection of nodes where each node contains a data payload, a pointer to the previous node (`prev`), and a pointer to the next node (`next`). | Enables bidirectional traversal; higher pointer memory overhead; allows single-pointer node deletions. |
| **Circular Singly Linked List (CSLL)** | A singly linked list variant wherein the terminal node's `next` pointer references the initial `head` node rather than $\text{NULL}$. | Eliminates null pointer checks; provides endless circular iteration for cyclic scheduling. |
| **Circular Doubly Linked List (CDLL)** | A doubly linked structure where the first node's `prev` references the last node, and the last node's `next` references the first node (`head`). | Unrestricted bidirectional traversal; permits $O(1)$ operations at both boundaries without maintaining explicit tail pointers. |

## 4. Detailed Structured Technical Lecture Notes

### I. Linear Queues: Array Implementation & False Overflow

#### Overview & Theoretical Foundation
A linear queue is an abstract data type adhering strictly to the First-In-First-Out (FIFO) scheduling paradigm. In a standard fixed-size array implementation, the underlying storage is allocated with capacity $\text{Max}$, spanning indices $0$ to $\text{Max} - 1$. Tracking state requires two integer index variables: $\text{front}$ and $\text{rear}$. An empty queue is formally denoted by $\text{front} = -1$ and $\text{rear} = -1$. As elements are enqueued, $\text{rear}$ advances; as elements are dequeued, $\text{front}$ advances forward.

#### Mechanics & Operational Invariants
1. **Queue Creation:** Initialize $\text{front} \leftarrow -1$, $\text{rear} \leftarrow -1$.
2. **Enqueue Procedure:**
   * Verify whether the queue is full: evaluate if $\text{rear} = \text{Max} - 1$. If true, trigger a Queue Overflow exception.
   * If $\text{front} = -1$ (queue is currently empty), reset $\text{front} \leftarrow 0$.
   * Increment $\text{rear} \leftarrow \text{rear} + 1$.
   * Assign $\text{Queue}[\text{rear}] \leftarrow \text{item}$.
3. **Dequeue Procedure:**
   * Verify whether the queue is empty: evaluate if $\text{front} = -1$. If true, trigger a Queue Underflow exception.
   * Retrieve $\text{item} \leftarrow \text{Queue}[\text{front}]$.
   * Evaluate termination state: if $\text{front} = \text{rear}$ (the final element was removed), reinitialize both pointers to signal emptiness: $\text{front} \leftarrow -1$, $\text{rear} \leftarrow -1$.
   * Otherwise, increment the front boundary: $\text{front} \leftarrow \text{front} + 1$.
   * Return $\text{item}$.
4. **Boundary & Edge Cases:**
   * Underflow occurs on dequeue or peek when $\text{front} = -1$.
   * False Overflow manifests when $\text{rear} = \text{Max} - 1$ while $\text{front} > 0$. The slots from index $0$ to $\text{front} - 1$ are vacant and inaccessible because the linear implementation lacks a backward wrapping mechanism. The system cannot allocate new items even though total utilization is less than capacity.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Create Queue** | $\Theta(1)$ | Constant-time variable initialization ($\text{front} \leftarrow -1, \text{rear} \leftarrow -1$). |
| **Enqueue** | $\Theta(1)$ | Direct array indexing via $\text{rear}$ pointer incrementation. |
| **Dequeue** | $\Theta(1)$ | Direct array access at $\text{front}$ followed by scalar pointer shift. |
| **Peek / Rear Read** | $\Theta(1)$ | Immediate dereference of $\text{Queue}[\text{front}]$ or $\text{Queue}[\text{rear}]$. |
| **Size Calculation** | $\Theta(1)$ | Evaluated as $\text{rear} - \text{front} + 1$ (returns $0$ if $\text{front} = -1$). |
| **Space Complexity** | $\Theta(\text{Max})$ | Fixed pre-allocated contiguous memory block. |

#### Design Trade-offs & Limitations
While linear queues feature $O(1)$ operations, they present severe spatial inefficiencies. As elements dequeue, the front pointer drifts toward the terminal index, leaving defunct memory slots at the front of the array that cannot be reclaimed by the queue or the operating system without shifting all elements leftward ($O(n)$ cost) or resetting after total drainage.

### II. Circular Queues

#### Overview & Theoretical Foundation
A circular queue resolves the false overflow defect of linear queues by conceptually mapping a linear array of size $\text{Max}$ into a continuous ring. When the rear pointer reaches $\text{Max} - 1$, the subsequent enqueue operation wraps around to index $0$, provided that slot is not occupied by the active front element. Structural index transitions are managed via modular arithmetic.

#### Mechanics & Operational Invariants
1. **Creation:** Initialize $\text{front} \leftarrow -1$, $\text{rear} \leftarrow -1$.
2. **Circular Enqueue:**
   * Overflow Condition: Check if $(\text{rear} + 1) \pmod{\text{Max}} = \text{front}$. If true, signal Queue Overflow.
   * If $\text{front} = -1$, assign $\text{front} \leftarrow 0, \text{rear} \leftarrow 0$.
   * Otherwise, advance the pointer circularly: $\text{rear} \leftarrow (\text{rear} + 1) \pmod{\text{Max}}$.
   * Assign $\text{Queue}[\text{rear}] \leftarrow \text{item}$.
3. **Circular Dequeue:**
   * Underflow Condition: Check if $\text{front} = -1$. If true, signal Queue Underflow.
   * Retrieve $\text{item} \leftarrow \text{Queue}[\text{front}]$.
   * If $\text{front} = \text{rear}$, the queue has been drained: reset $\text{front} \leftarrow -1, \text{rear} \leftarrow -1$.
   * Otherwise, advance the front pointer circularly: $\text{front} \leftarrow (\text{front} + 1) \pmod{\text{Max}}$.
   * Return $\text{item}$.
4. **Traversal / Display:**
   * Initialize loop iterator $i \leftarrow \text{front}$.
   * Loop: Print $\text{Queue}[i]$. If $i = \text{rear}$, terminate loop; otherwise update $i \leftarrow (i + 1) \pmod{\text{Max}}$.

#### Trace Example: Capacity = 5
1. Enqueue $10, 20, 30, 40, 50$: $\text{front} = 0$, $\text{rear} = 4$. Array is completely full.
2. Dequeue two items ($10, 20$): $\text{front}$ advances to index $2$. Indices $0$ and $1$ are now logically free.
3. Enqueue $60$: $\text{rear} = (4 + 1) \pmod 5 = 0$. $\text{Queue}[0] \leftarrow 60$. $\text{front} = 2$, $\text{rear} = 0$.
4. Enqueue $70$: $\text{rear} = (0 + 1) \pmod 5 = 1$. $\text{Queue}[1] \leftarrow 70$. $\text{front} = 2$, $\text{rear} = 1$.
5. Next enqueue check: $(1 + 1) \pmod 5 = 2 = \text{front}$. True overflow detected.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Enqueue Time** | $\Theta(1)$ | Evaluated via single modulo operation and direct array assignment. |
| **Dequeue Time** | $\Theta(1)$ | Direct element extraction followed by scalar pointer modulo increment. |
| **Display Time** | $\Theta(n)$ | Traverses all $n$ active elements sequentially from $\text{front}$ to $\text{rear}$. |
| **Auxiliary Space** | $\Theta(1)$ | Uses internal index markers without dynamic allocation. |

#### Design Trade-offs & Practical Applications
Circular queues maximize static array memory efficiency, precluding false overflows while preserving $O(1)$ operations. Primary practical applications include CPU process scheduling (Round-Robin), circular input/keyboard buffers, printer spoolers, and real-time network packet queuing.

### III. Dynamic Array Resizing & Amortized Complexity Analysis

#### Overview & Theoretical Foundation
When a static queue or stack reaches capacity under dynamic demands, the underlying runtime must resize the buffer to prevent permanent overflow. The standard scaling protocol doubles the array capacity ($2 \times \text{Max}$) and copies all existing $n$ items to the new contiguous memory allocation.

#### Theoretical Breakdown
* **Individual Cost:** A standard push/enqueue operation takes $O(1)$ time. When capacity $n$ is reached, the resize operation necessitates creating a new array of size $2n$ and copying $n$ elements, consuming $O(n)$ time.
* **Amortization Mechanic:** Because an $O(n)$ copy event occurs only after $n$ successive insertions, distributing the $O(n)$ copying overhead equally across all $n$ operations imputes a constant additional cost of $O(1)$ per operation:

$$\text{Amortized Cost} = \frac{\text{Total Time for } n \text{ Operations}}{n} = \frac{O(n) + n \cdot O(1)}{n} = O(1)$$

### IV. Double-Ended Queues (Deques)

#### Overview & Theoretical Foundation
A double-ended queue (Deque, pronounced "deck") is a generalized linear data structure permitting insertion and deletion operations at both extremities (front and rear). It synthesizes FIFO (queue-like) and LIFO (stack-like) behaviors into a unified structure, providing enhanced flexibility for bidirectional data pipelines.

#### Mechanics & Operational Invariants
* **Insert Front:** Shifts $\text{front}$ backward circularly: $\text{front} \leftarrow (\text{front} - 1 + \text{Max}) \pmod{\text{Max}}$, then writes element. If empty, $\text{front} \leftarrow \text{rear} \leftarrow 0$.
* **Insert Rear:** Shifts $\text{rear}$ forward circularly: $\text{rear} \leftarrow (\text{rear} + 1) \pmod{\text{Max}}$, then writes element.
* **Delete Front:** Reads $\text{Queue}[\text{front}]$, then advances $\text{front} \leftarrow (\text{front} + 1) \pmod{\text{Max}}$.
* **Delete Rear:** Reads $\text{Queue}[\text{rear}]$, then retracts $\text{rear} \leftarrow (\text{rear} - 1 + \text{Max}) \pmod{\text{Max}}$.
* **Overflow Check:** Validated when $(\text{rear} + 1) \pmod{\text{Max}} = \text{front}$.
* **Underflow Check:** Validated when $\text{front} = -1$.

#### Trace Example: Capacity = 5
1. Operations: $\text{InsertRear}(10)$, $\text{InsertRear}(20)$, $\text{InsertFront}(5)$, $\text{DeleteRear}()$, $\text{InsertFront}(2)$.
2. Trace sequence:
   * $\text{InsertRear}(10) \rightarrow \text{Queue}[0] = 10; \text{front} = 0, \text{rear} = 0$.
   * $\text{InsertRear}(20) \rightarrow \text{Queue}[1] = 20; \text{front} = 0, \text{rear} = 1$.
   * $\text{InsertFront}(5) \rightarrow \text{front}$ moves backward: $(0 - 1 + 5) \pmod 5 = 4$. $\text{Queue}[4] = 5; \text{front} = 4, \text{rear} = 1$.
   * $\text{DeleteRear}() \rightarrow 20$ removed; $\text{rear}$ moves backward: $(1 - 1 + 5) \pmod 5 = 0; \text{front} = 4, \text{rear} = 0$.
   * $\text{InsertFront}(2) \rightarrow \text{front}$ moves backward: $(4 - 1 + 5) \pmod 5 = 3$. $\text{Queue}[3] = 2; \text{front} = 3, \text{rear} = 0$.
3. Order from $\text{front}$ to $\text{rear}$: Reading from index $3 \rightarrow 4 \rightarrow 0$ yields $[2, 5, 10]$.

#### Complexity & Algorithmic Analysis
| Metric | Bound | Derivation / Justification from Lecture |
| :--- | :--- | :--- |
| **Insert Front / Rear** | $\Theta(1)$ | Direct pointer arithmetic via circular indexing. |
| **Delete Front / Rear** | $\Theta(1)$ | Direct array access followed by backward or forward pointer updates. |
| **Get Front / Rear** | $\Theta(1)$ | Instantaneous dereference at $\text{front}$ or $\text{rear}$ index. |
| **State Checks (Empty/Full)** | $\Theta(1)$ | Scalar comparisons. |

#### Design Trade-offs & Practical Applications
Deques introduce implementation complexity relative to standard queues due to double-direction boundary logic. Typical applications include undo-redo operational pipelines, browser history caching, sliding-window stream algorithms, and palindrome validation (verifying character equality simultaneously from opposing boundaries).

### V. Priority Queues (Min-PQ and Max-PQ)

#### Overview & Theoretical Foundation
A Priority Queue is an abstract data type where each stored entity consists of an information payload and an associated numeric priority key. Processing order ignores pure chronological arrival times in favor of priority rankings:
* **Max-Priority Queue:** Dequeues the element containing the largest priority value first.
* **Min-Priority Queue:** Dequeues the element containing the lowest priority value first.
* **Tie-Breaking Rule:** Elements possessing identical priority levels default to FIFO ordering.

#### Implementation Trade-off Matrix
The computational efficiency of a Priority Queue is directly governed by its underlying data architecture:

| Underlying Data Structure | Insertion Complexity | Deletion Complexity (Extract Min/Max) | Peek Complexity | Lecture Justification |
| :--- | :--- | :--- | :--- | :--- |
| **Unsorted Array** | $O(1)$ | $O(n)$ | $O(n)$ | Insertion writes to next free slot ($O(1)$); deletion/peek requires a linear scan across $n$ elements to discover highest/lowest priority. |
| **Sorted Array / List** | $O(n)$ | $O(1)$ | $O(1)$ | Requires sequential traversal to locate the exact sorted rank for insertion ($O(n)$); extraction occurs immediately from the boundary ($O(1)$). |
| **Binary Heap** | $O(\log n)$ | $O(\log n)$ | $O(1)$ | Tree-based balancing maintains heap-order property; covered comprehensively in Chapter 3. |

#### Trace Example: Max-Priority Queue Processing
1. Queue Sequence: $\text{Insert}(A, 2), \text{Insert}(B, 5), \text{Insert}(C, 3), \text{Delete}(), \text{Insert}(D, 4)$.
2. Extraction: $\text{Delete}()$ identifies element with highest priority ($B, 5$).
3. Insertion: $D$ is enqueued with priority $4$.
4. Remaining Queue Sorted by Priority: $D(4) \rightarrow C(3) \rightarrow A(2)$.

### VI. Sequential List ADT: Array Implementation

#### Overview & Theoretical Foundation
An array-based list stores elements within contiguous physical memory addresses, enabling constant-time random access via direct offset indexing:

$$\text{Address}(\text{List}[i]) = \text{Base Address} + i \times \text{Size of Element}$$

For a base address of $1000$ and 4-byte integers, the address for index $5$ evaluates to:

$$\text{Address}(\text{List}[5]) = 1000 + 5 \times 4 = 1020$$

#### Operational Inefficiencies
* **Positional Insertion:** Inserting an item at arbitrary index $P$ requires shifting all trailing elements from index $\text{Size} - 1$ down to $P$ one position rightward ($O(n)$ worst-case at index $0$).
* **Positional Deletion:** Deleting an item at index $P$ necessitates shifting elements from index $P + 1$ to $\text{Size} - 1$ one position leftward ($O(n)$).
* **Terminal Operations:** Appending or deleting strictly at the terminal index ($\text{Size} - 1$) circumvents element shifting, executing in $O(1)$ time.

### VII. Linked Lists: Structural Variants & Pointer Mechanics

#### Overview & Theoretical Foundation
Linked lists replace rigid, contiguous memory requirements with dynamically allocated independent nodes linked via pointer references. Each node encapsulates a data payload alongside directional pointer fields.

```
Singly Linked Node:
+------------+------------+
|    Data    |    Next    |
+------------+------------+

Doubly Linked Node:
+------------+------------+------------+
|    Prev    |    Data    |    Next    |
+------------+------------+------------+
```

#### Detailed Variant Mechanics

```
Singly Linked List (SLL):
Head -> [ Data | Next ] -> [ Data | Next ] -> NULL

Doubly Linked List (DLL):
NULL <- [ Prev | Data | Next ] <-> [ Prev | Data | Next ] -> NULL

Circular Singly Linked List (CSLL):
Head -> [ Data | Next ] -> [ Data | Next ] --+
  ^                                          |
  +------------------------------------------+

Circular Doubly Linked List (CDLL):
  +----------------------------------------------------+
  |                                                    |
  v                                                    v
[ Prev | Data | Next ] <-> [ Prev | Data | Next ] <-> [ Prev | Data | Next ]
  ^                                                    ^
  +----------------------------------------------------+
```

1. **Singly Linked List (SLL):**
   * *Insert at Beginning ($O(1)$):* Allocate `NewNode`; set $\text{NewNode.data} \leftarrow \text{item}$; $\text{NewNode.next} \leftarrow \text{Head}$; $\text{Head} \leftarrow \text{NewNode}$.
   * *Insert at End ($O(n)$):* Traverse list using a temporary pointer until $\text{temp.next} = \text{NULL}$; assign $\text{temp.next} \leftarrow \text{NewNode}$.
   * *Delete Given Item ($O(n)$):* Requires tracking two running pointers: `prev` and `curr`. When target is located: $\text{prev.next} \leftarrow \text{curr.next}$; deallocate `curr`.
2. **Doubly Linked List (DLL):**
   * Incorporates `prev` and `next` pointers, permitting full bidirectional traversal.
   * *Node Deletion via Single Pointer ($O(1)$ given direct node handle):* Rebind adjacent neighbors directly without independent list traversal:
     $$\text{temp.prev.next} \leftarrow \text{temp.next}$$
     $$\text{temp.next.prev} \leftarrow \text{temp.prev}$$
     Deallocate `temp`.
3. **Circular Singly Linked List (CSLL):**
   * The terminal node references $\text{Head}$ instead of $\text{NULL}$.
   * Traversal loop invariant: continue advancing until $\text{temp.next} = \text{Head}$.
   * *Insert at Beginning ($O(n)$ without tail pointer):* Must locate the terminal node via linear traversal to reassign its `next` pointer to the newly allocated head node.
4. **Circular Doubly Linked List (CDLL):**
   * Combines circularity and bidirectional linking. $\text{Head.prev}$ directly accesses the terminal node, and $\text{Tail.next}$ directly references $\text{Head}$.
   * *Insert at Beginning / End ($O(1)$):* Immediate access to the terminal node via $\text{Head.prev}$ allows instant pointer adjustments without linear traversal.
   * *Positional Navigation:* If size $n$ is known, an insertion at position $P > n/2$ can traverse backward from $\text{Head.prev}$, requiring fewer than $n/2$ step iterations.

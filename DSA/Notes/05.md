## 2. Key Concepts & Definitions

*   **FIFO (First-In-First-Out):** The fundamental principle of a queue where the first element added is the first to be removed.
*   **Front Pointer:** Points to the element at the beginning of the queue (used for deletion).
*   **Rear Pointer:** Points to the element at the end of the queue (used for insertion).
*   **Queue Overflow:** A condition where an attempt is made to insert an element into a full queue.
*   **Queue Underflow:** A condition where an attempt is made to delete an element from an empty queue.
*   **False Overflow:** In linear queues, when the `rear` reaches the last index but empty spaces exist at the front due to previous deletions.
*   **Circular Queue:** A queue where the last position is logically connected back to the first position to reuse memory.
*   **Priority Queue:** A queue where each element has an associated priority; elements with higher priority are served before those with lower priority.
*   **Deque (Double-Ended Queue):** A specialized queue allowing insertion and deletion from both the front and the rear.
*   **Node:** The basic building block of a linked list, containing a `data` field and one or more `pointer` fields.
*   **Head Pointer:** A pointer that stores the memory address of the first node in a linked list.
*   **Tail Pointer:** A pointer (often used in advanced lists) that stores the address of the last node.
*   **Amortized Complexity:** The average time taken per operation over a sequence of operations, accounting for occasional expensive steps (e.g., resizing an array).

## 3. Detailed Structured Lecture Notes

### I. Linear Queue Operations and Limitations
*   **Basic Operations:**
    *   **Create Queue:** Initializes `front` and `rear` pointers to -1, indicating an empty state.
    *   **Enqueue:** Checks for overflow (`rear == max - 1`). If not full, `rear` increments, and the item is added. If it's the first item, `front` is set to 0.
    *   **Dequeue:** Checks for underflow (`front == -1`). If not empty, the item at `front` is removed. If `front == rear`, the queue becomes empty again, and both are reset to -1.
    *   **Peek/Front:** Returns the element at the front without removing it.
*   **Limitations of Linear Queues:**
    *   **Memory Wastage:** As elements are dequeued, the `front` pointer moves forward, leaving unusable empty slots at the start of the array.
    *   **False Overflow:** The `rear` pointer can reach the end of the array while the front of the array is empty, preventing further insertions.

### II. Circular Queues
*   **Mechanism:** Uses the modulo operator to "wrap" the `rear` pointer back to index 0 once it reaches `max - 1`.
    *   `rear = (rear + 1) % max`
*   **Full Condition:** A circular queue is full when `(rear + 1) % max == front`.
*   **Advantages:** Efficiently utilizes all available memory slots and avoids false overflow.
*   **Applications:** CPU scheduling, circular buffers (keyboard/printer buffers), and network packet buffering.

### III. Priority Queues
*   **Serving Logic:** Serves elements based on priority level rather than arrival time. If priorities are equal, FIFO is applied.
*   **Types:**
    *   **Max-Priority Queue:** The element with the highest priority value is removed first.
    *   **Min-Priority Queue:** The element with the lowest priority value is removed first.
*   **Complexity (using Binary Heap):**
    *   Insertion: $O(\log n)$
    *   Deletion: $O(\log n)$
    *   Peek: $O(1)$

### IV. Double-Ended Queues (Deque)
*   **Flexibility:** Supports `InsertFront`, `InsertRear`, `DeleteFront`, and `DeleteRear`.
*   **Applications:** Palindrome checking (comparing front and back), undo/redo operations in software, and browser history navigation.

### V. Array-Based Lists
*   **Characteristics:** Contiguous memory, fixed size, and fast random access via indices ($O(1)$).
*   **Address Calculation:** For an array $A$, the address of $A[i]$ is calculated as: `Base Address + (index * size of element)`.
*   **Limitations:** Insertion and deletion in the middle are expensive ($O(n)$) as they require shifting all subsequent elements.

### VI. Singly Linked Lists
*   **Structure:** Each node contains `data` and a `next` pointer.
*   **Insert at Beginning:** $O(1)$ complexity. Create a new node, point its `next` to the current `head`, and update `head` to the new node.
*   **Insert at Position/End:** Requires traversal, resulting in $O(n)$ complexity.
*   **Search/Traversal:** Must visit nodes sequentially starting from the `head`.

### VII. Doubly Linked Lists
*   **Structure:** Each node contains `prev`, `data`, and `next` pointers.
*   **Advantages:** Can be traversed in both directions. Deletion is easier because you have immediate access to the previous node.
*   **Disadvantages:** Requires extra memory for the additional `prev` pointer and more complex pointer manipulation during updates.

### VIII. Circular Linked Lists
*   **Singly Circular:** The `next` pointer of the last node points back to the `head`. This allows for continuous looping through the list.
*   **Doubly Circular:** The `next` of the last node points to the `head`, and the `prev` of the `head` points to the last node.
*   **Use Cases:** Round-robin scheduling and multiplayer games where turns rotate through a list of players.

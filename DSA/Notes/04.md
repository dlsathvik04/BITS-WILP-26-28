## 2. Key Concepts & Definitions

- **Stack:** A linear data structure that follows the LIFO principle where elements are inserted and removed from the same end (the Top).
- **Queue:** A linear data structure following the FIFO principle where elements are inserted at the Rear and removed from the Front.
- **LIFO (Last-In-First-Out):** The principle where the last element added is the first to be removed (e.g., a stack of plates).
- **FIFO (First-In-First-Out):** The principle where the first element added is the first to be removed (e.g., a ticket counter line).
- **ADT (Abstract Data Type):** A model for a data type where the behavior is defined by a set of values and operations, but the implementation is hidden.
- **Infix Notation:** Operators are written between operands (e.g., $A + B$).
- **Prefix Notation (Polish Notation):** Operators are written before operands (e.g., $+AB$).
- **Postfix Notation (Reverse Polish Notation):** Operators are written after operands (e.g., $AB+$).
- **Stack Overflow:** An error condition that occurs when an attempt is made to push an item onto a stack that is already at its maximum capacity.
- **Stack Underflow:** An error condition occurring when an attempt is made to pop or peek from an empty stack.
- **Amortized Complexity:** The average time taken per operation over a worst-case sequence of operations. In dynamic stacks, resizing takes $O(N)$, but the amortized cost remains $O(1)$.
- **Precedence/Priority:** The rules determining the order of operations (e.g., multiplication has higher priority than addition).

## 3. Detailed Structured Lecture Notes

### I. Review of Data Structures
- **Classification:**
    - **Linear:** Data elements arranged in a sequence (e.g., Arrays, Lists, Stacks, Queues).
    - **Non-Linear:** Data elements not in a sequence (e.g., Trees, Graphs).
    - **Static:** Fixed size allocated at compile-time.
    - **Dynamic:** Size can grow or shrink during execution.
- **ADT Concept:** Stacks and Queues are viewed as "black boxes." We care about the operations (Push/Pop) rather than whether they are implemented via an array or a linked list.

### II. The Stack ADT
- **LIFO Principle:** The top element is the only accessible element.
- **Standard Operations:**
    - `Create()`: Initializes the stack, setting the `top` pointer to -1.
    - `Push(item)`: Increments `top` and adds an element.
    - `Pop()`: Returns the `top` element and decrements `top`.
    - `Peek()`: Returns the value of the `top` element without removing it.
    - `isEmpty()`: Checks if `top == -1`.
    - `isFull()`: Checks if `top == max - 1`.
    - `Size()`: Returns `top + 1`.
- **Real-World Examples:**
    - Stacks of plates, books, or cups.
    - Browser history (Back button).
    - Undo/Redo operations in text editors.
    - Function call stacks in programming (Recursion).

### III. Time Complexity and Amortized Analysis
- **Standard Time Complexity:** All basic stack operations (Push, Pop, Peek, etc.) are $O(1)$.
- **Dynamic Resizing:**
    - When a stack is full, the system typically assigns a new stack of double the size ($2 \times \text{Max}$).
    - All existing elements are copied to the new memory location.
    - While the single "Push" that triggers resizing takes $O(N)$ time, the **Amortized Complexity** over many operations remains $O(1)$ because resizing happens infrequently.

### IV. Arithmetic Expressions and Stacks
- **Types of Expressions:**
    - **Infix:** Standard human-readable form. Requires brackets and precedence rules (BODMAS).
    - **Prefix/Postfix:** Machine-friendly. Brackets are not required because the order of operations is explicit.
- **Postfix Evaluation Algorithm:**
    1. Scan from left to right.
    2. If operand: Push to stack.
    3. If operator: Pop two operands, apply the operator, and push the result back.
    4. Repeat until the end of the expression.
- **Infix to Postfix Conversion:**
    - Operands are printed immediately.
    - Operators are pushed to a stack. If a new operator has lower or equal precedence than the one on top, the top is popped and printed before the new one is pushed.
    - Brackets have the highest priority; everything inside a bracket is processed immediately once the closing bracket is encountered.

### V. Bracket Matching
- Stacks are used to ensure parentheses `()`, square brackets `[]`, and curly braces `{}` are balanced.
- **Logic:**
    - Scan the expression.
    - Push every opening bracket onto the stack.
    - For every closing bracket, check if the stack is empty (Underflow = invalid).
    - If not empty, pop and check if the popped opening bracket matches the current closing bracket.
    - If the stack is empty at the end of the expression, it is balanced.

### VI. Tower of Hanoi
- **Goal:** Move $N$ disks from Source (A) to Destination (C) using an auxiliary peg (B).
- **Rules:** Only one disk moves at a time; a larger disk cannot be placed on a smaller disk.
- **Complexity:** The number of moves required is $2^n - 1$. This leads to $O(2^n)$ time complexity.
- **Stack Involvement:** Each peg acts as a stack. The recursive calls effectively push and pop states from the system's function call stack.

### VII. The Queue ADT
- **FIFO Principle:** First element in is the first out.
- **Standard Operations:**
    - `nQ` (Enqueue): Add to the `Rear`.
    - `dQ` (Dequeue): Remove from the `Front`.
- **Implementation Logic:**
    - Uses two pointers: `Front` and `Rear`.
    - Initial state: `Front = -1`, `Rear = -1`.
    - When the first item is added, both are set to 0.
    - `nQ` increments `Rear`; `dQ` increments `Front`.
    - If `Rear == Max - 1`, the queue is full (Overflow).
    - If `Front > Rear` or `Front == -1`, the queue is empty (Underflow).

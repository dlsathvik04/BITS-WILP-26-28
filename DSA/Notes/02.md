## 2. Key Concepts & Definitions

* **Algorithm:** A finite, unambiguous, step-by-step sequence of clear, executable instructions that processes inputs to produce desired outputs for a well-defined computational problem.
* **Definiteness:** The property that each step of an algorithm must be completely clear, unambiguous, and precisely specified.
* **Finiteness:** The requirement that an algorithm must always terminate after a limited, finite number of steps for any valid input instance.
* **Effectiveness:** The requirement that every operation in an algorithm must be sufficiently basic to be carried out feasibly in finite time by a machine or human.
* **Random Access Machine (RAM) Model:** An abstract computational model assuming a single processor, purely sequential execution, unlimited memory, unit-time $O(1)$ memory access, and unit-time basic operations.
* **Time Complexity $T(n)$:** The total execution time or total number of elementary operations performed by an algorithm expressed as a function of the input size $n$.
* **Best-Case Time Complexity:** The minimum running time over all possible input instances of size $n$.
* **Worst-Case Time Complexity:** The maximum running time over all possible input instances of size $n$ (provides a guaranteed upper bound).
* **Average-Case Time Complexity:** The expected running time averaged over all possible input instances of size $n$, weighted by their probability distribution.
* **Big-O Notation ($\mathcal{O}$):** Represents an asymptotic **upper bound**. $T(n) = \mathcal{O}(g(n))$ if $\exists\, c > 0, n_0 > 0$ such that $T(n) \le c \cdot g(n)$ for all $n \ge n_0$.
* **Big-Omega Notation ($\Omega$):** Represents an asymptotic **lower bound**. $T(n) = \Omega(g(n))$ if $\exists\, c > 0, n_0 > 0$ such that $T(n) \ge c \cdot g(n)$ for all $n \ge n_0$.
* **Big-Theta Notation ($\Theta$):** Represents an asymptotic **tight bound**. $T(n) = \Theta(g(n))$ if $\exists\, c_1, c_2 > 0, n_0 > 0$ such that $c_1 \cdot g(n) \le T(n) \le c_2 \cdot g(n)$ for all $n \ge n_0$.
* **Recurrence Relation:** An equation or inequality that defines a function $T(n)$ over the integers in terms of its value on smaller inputs (e.g., $T(n) = T(n-1) + C$).
* **Master Theorem:** A systematic recipe for solving divide-and-conquer recurrences of the form $T(n) = aT(n/b) + f(n)$ or decreasing recurrences of the form $T(n) = aT(n-b) + f(n)$.

## 3. Detailed Structured Lecture Notes

### 3.1 Introduction to Algorithms & Specifications

An algorithm is a step-by-step computational procedure used to solve a problem. 

#### Mandatory Characteristics of an Algorithm
1. **Input:** Zero or more externally supplied quantities. (Note: Some algorithms operate without explicit external input by fetching data internally, e.g., reading system clock time).
2. **Output:** At least one output quantity produced that has a specific relation to the inputs.
3. **Definiteness:** Each instruction must be clear, precise, and unambiguous.
   * *Counter-Example:* "Heat the solution for a while" (ambiguous time) vs. "Boil the water for exactly 3 minutes" (definite).
   * *Counter-Example:* `if (a < 1 AND a > 3)` $\rightarrow$ logically impossible condition.
4. **Finiteness:** For all input instances, the algorithm must terminate after a finite number of steps.
5. **Effectiveness:** Every instruction must be basic enough that it can be carried out in practice within finite time using basic arithmetic or logical operations.

#### Real-World Analogies
* **Friend Search in a Library:** Navigating reception, floors, reading room, and computer lab in a structured sequence until the friend is found or all locations are checked.
* **Tea Preparation:** Step-by-step sequence (boil water, add tea leaves, boil 2-3 mins, add milk/sugar, filter, serve).
* **ATM Cash Withdrawal:** Insert card $\rightarrow$ Enter PIN $\rightarrow$ System verifies PIN $\rightarrow$ Select withdrawal $\rightarrow$ Enter amount $\rightarrow$ Balance check $\rightarrow$ Dispense cash $\rightarrow$ Update balance $\rightarrow$ Print receipt $\rightarrow$ Terminate.

### 3.2 Algorithm vs. Program vs. Procedure

| Characteristic | Algorithm | Program | Procedure |
| :--- | :--- | :--- | :--- |
| **Language Dependency** | High-level, language-independent (pseudocode/math) | Written in a specific programming language (C, Python, Java) | Language-independent or dependent |
| **Execution** | Conceptual logic; cannot run directly on hardware | Executable directly by hardware or an interpreter | Sequence of actions |
| **Finiteness** | **Must** terminate after finite steps | May run infinitely (e.g., OS Kernel, web servers) | May or may not terminate |
| **Output** | Must produce at least one output | May or may not produce user output | May or may not produce output |

### 3.3 Methods of Representing Algorithms

1. **Natural Language:** Plain English/text. Easy for humans, but prone to ambiguity and vagueness.
2. **Flowcharts:** Graphical representation using standard geometric symbols:
   * *Oval:* Start/Stop terminal.
   * *Parallelogram:* Input/Output operations.
   * *Rectangle:* Computational steps/process.
   * *Diamond:* Decision making (If/Else).
   * *Arrows/Lines:* Sequence flow control.
   * *Circles:* On-page/off-page connectors.
3. **Pseudocode:** An informal, high-level description of an algorithm combining natural language with programming language structures (loops, conditionals, assignments). It omits language-specific syntax overhead (like memory management, header includes).

### 3.4 Computational Models & The RAM Model

#### Why Physical Benchmarking (Wall-Clock Measurement) Fails
Measuring runtime by running code on a computer fails as an algorithm comparison metric because it is heavily influenced by external variables:
* Processor speed and microarchitecture variations.
* Available RAM and cache size ($L1/L2/L3$).
* Compiler optimizations and language runtime efficiency (e.g., C vs. Python).
* Operating system overhead and background process multitasking.

#### The Random Access Machine (RAM) Model
To evaluate algorithms independently of physical hardware, computer scientists use the **RAM Computational Model**:
* **Processor:** Single-processor system that executes instructions sequentially (no parallel processing).
* **Memory Access:** Unlimited memory where accessing any memory location takes constant time ($O(1)$), regardless of location index.
* **Basic Operations:** Elementary operations (addition, subtraction, multiplication, division, assignment, comparisons, logical operations) take exactly **1 unit of time**.
* **Sequential Flow:** Control flows line-by-line unless interrupted by control structures.

#### Limitations of the RAM Model
* Ignores memory hierarchy (cache misses vs. main RAM vs. disk I/O costs are treated identically).
* Ignores multi-core/parallel architecture speedups.
* Assumes fixed-size basic operations regardless of operand magnitude (e.g., 64-bit addition vs. 10,000-digit number addition).

### 3.5 Characterizing Running Time & Input Instances

Time complexity $T(n)$ is analyzed as a function of input size $n$ (e.g., number of elements in an array, number of vertices in a graph).

#### Input Instance Cases
1. **Best-Case Time Complexity:** Running time under the most favorable input instance of size $n$.
   * *Example (Linear Search):* Target element is found at the very first index ($A[0]$). $T_{\text{best}}(n) = O(1)$.
2. **Worst-Case Time Complexity:** Running time under the most unfavorable input instance of size $n$. Provides a strict upper guarantee.
   * *Example (Linear Search):* Target element is at the last position ($A[n-1]$) or not present at all. $T_{\text{worst}}(n) = O(n)$.
3. **Average-Case Time Complexity:** Expected running time over all valid input instances of size $n$, assuming a uniform probability distribution.
   * *Example (Linear Search):* Target is equally likely to be at any index from $0$ to $n-1$. Average comparisons = $\frac{1+2+...+n}{n} = \frac{n+1}{2} \implies O(n)$.

*Note on Array Max Search:* Finding the maximum element in an unsorted array of size $n$ requires scanning all $n$ elements. Thus, Best-case, Worst-case, and Average-case are all $\Theta(n)$.

### 3.6 Asymptotic Notations & Growth Rates

Asymptotic notation describes the behavior of $T(n)$ as $n \to \infty$.

```
    Upper Bound (Big-O)         Lower Bound (Big-Omega)        Tight Bound (Big-Theta)
    
       c*g(n)                        T(n)                         c2*g(n)
        /                             /                             /
       /   T(n)                      /                             /   T(n)
      /   /                         /   c*g(n)                    /   /
     /   /                         /   /                         /   /
    /   /                         /   /                         /   /
   /___/                         /___/                         /___/ c1*g(n)
  0    n0                       0    n0                       0    n0
```

#### Definitions

1. **Big-O ($\mathcal{O}$) — Asymptotic Upper Bound:**
   $$T(n) = \mathcal{O}(g(n)) \iff \exists\, c > 0, n_0 > 0 \text{ such that } 0 \le T(n) \le c \cdot g(n) \quad \forall n \ge n_0$$

2. **Big-Omega ($\Omega$) — Asymptotic Lower Bound:**
   $$T(n) = \Omega(g(n)) \iff \exists\, c > 0, n_0 > 0 \text{ such that } 0 \le c \cdot g(n) \le T(n) \quad \forall n \ge n_0$$

3. **Big-Theta ($\Theta$) — Asymptotic Tight Bound:**
   $$T(n) = \Theta(g(n)) \iff T(n) = \mathcal{O}(g(n)) \text{ and } T(n) = \Omega(g(n))$$
   $$\iff \exists\, c_1, c_2 > 0, n_0 > 0 \text{ such that } 0 \le c_1 \cdot g(n) \le T(n) \le c_2 \cdot g(n) \quad \forall n \ge n_0$$

4. **Small-o ($o$) — Strict Upper Bound:**
   $$T(n) = o(g(n)) \iff \lim_{n \to \infty} \frac{T(n)}{g(n)} = 0$$

5. **Small-omega ($\omega$) — Strict Lower Bound:**
   $$T(n) = \omega(g(n)) \iff \lim_{n \to \infty} \frac{T(n)}{g(n)} = \infty$$

#### Common Order of Growth Hierarchy (Increasing Order)
$$\mathcal{O}(1) < \mathcal{O}(\log n) < \mathcal{O}(\sqrt{n}) < \mathcal{O}(n) < \mathcal{O}(n \log n) < \mathcal{O}(n^2) < \mathcal{O}(n^3) < \mathcal{O}(2^n) < \mathcal{O}(n!)$$

#### Mathematical Properties
* **Transitivity:** If $f(n) = \mathcal{O}(g(n))$ and $g(n) = \mathcal{O}(h(n))$, then $f(n) = \mathcal{O}(h(n))$.
* **Reflexivity:** $f(n) = \mathcal{O}(f(n))$, $f(n) = \Omega(f(n))$, $f(n) = \Theta(f(n))$.
* **Symmetry:** $f(n) = \Theta(g(n)) \iff g(n) = \Theta(f(n))$.
* **Transpose Symmetry:** $f(n) = \mathcal{O}(g(n)) \iff g(n) = \Omega(f(n))$.

### 3.7 Step-Counting Method for Iterative Algorithms

To analyze an iterative algorithm, assign cost $c_i$ to each execution line and multiply by its total execution frequency $f_i$:

#### Example: Finding Maximum in an Array

```python
def find_max(A, n):
    max_val = A[0]         # Cost c1, Executed 1 time
    i = 1                  # Cost c2, Executed 1 time
    while i < n:           # Cost c3, Executed n times
        if A[i] > max_val: # Cost c4, Executed (n-1) times
            max_val = A[i] # Cost c5, Executed k times (0 <= k <= n-1)
        i = i + 1          # Cost c6, Executed (n-1) times
    return max_val         # Cost c7, Executed 1 time
```

* **Best Case ($k=0$):** Array sorted descending.
  $$T_{\text{best}}(n) = c_1 + c_2 + c_3 \cdot n + c_4(n-1) + c_6(n-1) + c_7 = C_1 n + C_2 = \Theta(n)$$
* **Worst Case ($k=n-1$):** Array sorted ascending.
  $$T_{\text{worst}}(n) = C_3 n + C_4 = \Theta(n)$$

### 3.8 Analyzing Recursive Algorithms & Recurrence Relations

When an algorithm calls itself recursively on a smaller input size, its running time is described by a **recurrence relation**.

#### Common Algorithm Recurrences

1. **Recursive Factorial:**
   $$T(n) = \begin{cases} \Theta(1) & \text{if } n = 0 \\ T(n-1) + \Theta(1) & \text{if } n > 0 \end{cases} \implies T(n) = \Theta(n)$$

2. **Recursive Binary Search:**
   $$T(n) = T(n/2) + \Theta(1) \implies T(n) = \Theta(\log n)$$

3. **Merge Sort:**
   $$T(n) = 2T(n/2) + \Theta(n) \implies T(n) = \Theta(n \log n)$$

4. **Recursive Fibonacci (Naive):**
   $$T(n) = T(n-1) + T(n-2) + \Theta(1) \implies T(n) = \Theta(2^n)$$

---

### 3.9 Methods for Solving Recurrence Relations

#### Method 1: Substitution Method (Guess & Prove via Induction)
1. Guess the form of the solution.
2. Use mathematical induction to find constants $c$ and $n_0$ that prove the bound.

#### Method 2: Recursion Tree Method
1. Draw a tree where each node represents the cost of a single subproblem.
2. Sum the costs across each level of the tree.
3. Determine the depth/height of the tree.
4. Sum up costs across all levels to find total work.

#### Method 3: Master Theorem

##### Case A: Divide-and-Conquer Recurrences
For recurrences of the form $T(n) = aT(n/b) + f(n)$, where $a \ge 1, b > 1$, and $f(n)$ is a positive function:

Let $E = \log_b a$ (critical exponent). Compare $f(n)$ with $n^E$:

* **Case 1:** If $f(n) = \mathcal{O}(n^{\log_b a - \epsilon})$ for some $\epsilon > 0$, then:
  $$T(n) = \Theta(n^{\log_b a})$$
* **Case 2:** If $f(n) = \Theta(n^{\log_b a} \log^k n)$ for $k \ge 0$, then:
  $$T(n) = \Theta(n^{\log_b a} \log^{k+1} n)$$
* **Case 3:** If $f(n) = \Omega(n^{\log_b a + \epsilon})$ for some $\epsilon > 0$, and if $a f(n/b) \le c f(n)$ for some $c < 1$ (regularity condition), then:
  $$T(n) = \Theta(f(n))$$

##### Case B: Decreasing Recurrences
For recurrences of the form $T(n) = aT(n-b) + f(n)$, where $a > 0, b > 0$, and $f(n) = \mathcal{O}(n^k)$ ($k \ge 0$):

* If $a < 1 \implies T(n) = \mathcal{O}(f(n))$
* If $a = 1 \implies T(n) = \mathcal{O}(n \cdot f(n)) = \mathcal{O}(n^{k+1})$
* If $a > 1 \implies T(n) = \mathcal{O}(a^{n/b} \cdot f(n))$

## 4. Discussion & Q&A Highlights

### Q1: Can an algorithm have zero inputs?
**Instructor's Answer:** Yes. An algorithm requires zero or more inputs. An algorithm can take zero inputs if the data is hardcoded or generated internally (e.g., generating system time, printing a fixed pattern, or calculating a hardcoded mathematical series).

### Q2: What is the practical difference between effectiveness and definiteness?
**Instructor's Answer:**
* **Definiteness** refers to clarity and lack of ambiguity. Every statement must have exactly one unambiguous interpretation.
* **Effectiveness** refers to feasibility. Even if a statement is clear (definite), it must be basic enough that a system or human can actually execute it within finite time using basic arithmetic or logic.

### Q3: If an Operating System kernel runs infinitely until the computer is powered down, is it an algorithm?
**Instructor's Answer:** Strictly speaking, no. An operating system is a **program** or a **procedure**, not an algorithm. An algorithm *must* guarantee termination after a finite number of steps for every valid input. Programs like OS kernels, web servers, and embedded control systems are designed to run indefinitely and therefore do not fulfill the finiteness condition required of pure algorithms.

### Q4: Why is `if (a < 1 and a > 3)` considered a violation of algorithm principles?
**Instructor's Answer:** A single numeric variable `a` cannot be simultaneously strictly less than 1 and strictly greater than 3. The condition is logically impossible and contradictory. Writing such logic reflects a violation of **definiteness** because it lacks valid computational sense and leads to dead/unreachable logic.

### Q5: Why don't we measure algorithm efficiency using clock time (seconds) on a real computer?
**Instructor's Answer:** Physical wall-clock time depends heavily on hardware factors like CPU frequency, available RAM, compiler optimizations, language runtimes, and concurrent background operating system tasks. A faster computer can make an inefficient algorithm appear faster than an efficient one running on an older machine. Theoretical analysis using abstract models (like the RAM machine) and asymptotic notation ($\mathcal{O}, \Omega, \Theta$) allows us to measure algorithmic efficiency independently of hardware.

1. Which characteristic of an algorithm specifies that every operation must be clear, unambiguous, and have only one interpretation?
   * A. Finiteness
   * B. Effectiveness
   * C. Definiteness
   * D. Feasibility
   * **Answer: C**
   * *Explanation:* Definiteness demands that instructions are clear and unambiguous. Finiteness demands termination; effectiveness demands feasibility.

2. Which of the following is **NOT** an assumption made by the Random Access Machine (RAM) computational model?
   * A. Elementary arithmetic operations take 1 unit of time.
   * B. Memory access time varies based on the physical distance of the memory address from the CPU.
   * C. Instructions are executed sequentially one after another.
   * D. Memory capacity is assumed to be unlimited.
   * **Answer: B**
   * *Explanation:* The RAM model explicitly assumes uniform constant-time ($O(1)$) access for any memory location regardless of its address.

3. Which of the following correctly orders the asymptotic growth rates from slowest to fastest?
   * A. $\mathcal{O}(1) < \mathcal{O}(n) < \mathcal{O}(\log n) < \mathcal{O}(n^2)$
   * B. $\mathcal{O}(\log n) < \mathcal{O}(n) < \mathcal{O}(n \log n) < \mathcal{O}(2^n)$
   * C. $\mathcal{O}(n) < \mathcal{O}(n \log n) < \mathcal{O}(\sqrt{n}) < \mathcal{O}(n^2)$
   * D. $\mathcal{O}(n^2) < \mathcal{O}(n \log n) < \mathcal{O}(n!) < \mathcal{O}(2^n)$
   * **Answer: B**
   * *Explanation:* The correct hierarchy is logarithmic ($\log n$) < linear ($n$) < linearithmic ($n \log n$) < exponential ($2^n$).

4. What is the solution to the recurrence relation $T(n) = T(n-1) + \Theta(1)$ with $T(1) = \Theta(1)$?
   * A. $\Theta(\log n)$
   * B. $\Theta(n)$
   * C. $\Theta(n \log n)$
   * D. $\Theta(n^2)$
   * **Answer: B**
   * *Explanation:* Expanding $T(n) = T(n-1) + c = T(n-2) + 2c = ... = T(1) + (n-1)c = \Theta(n)$.

5. Using the Master Theorem, what is the asymptotic time complexity of $T(n) = 4T(n/2) + n$?
   * A. $\Theta(n)$
   * B. $\Theta(n \log n)$
   * C. $\Theta(n^2)$
   * D. $\Theta(n^{\log_2 3})$
   * **Answer: C**
   * *Explanation:* Here $a=4, b=2, f(n)=n$. Calculate $n^{\log_b a} = n^{\log_2 4} = n^2$. Since $f(n) = n = \mathcal{O}(n^{2 - \epsilon})$ for $\epsilon=1$, Case 1 applies. Thus $T(n) = \Theta(n^2)$.

### 5.2 Conceptual & Analytical Problems

#### Problem 1: Formal Definitions & Comparisons
Provide formal mathematical definitions for $\mathcal{O}(g(n))$, $\Omega(g(n))$, and $\Theta(g(n))$. Prove that if $f(n) = 3n^2 + 5n + 2$, then $f(n) = \Theta(n^2)$.

**Solution:**
1. **Definitions:** Refer to Section 3.6 of these notes.
2. **Proof that $3n^2 + 5n + 2 = \Theta(n^2)$:**
   We need to find positive constants $c_1, c_2,$ and $n_0$ such that:
   $$c_1 n^2 \le 3n^2 + 5n + 2 \le c_2 n^2 \quad \forall n \ge n_0$$

   * **Upper bound ($c_2$):**
     For $n \ge 1$:
     $$3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10n^2$$
     So $c_2 = 10$ for $n_0 = 1$.

   * **Lower bound ($c_1$):**
     For $n \ge 1$:
     $$3n^2 + 5n + 2 \ge 3n^2$$
     So $c_1 = 3$ for $n_0 = 1$.

   Since $3n^2 \le 3n^2 + 5n + 2 \le 10n^2$ holds for all $n \ge 1$ with $c_1 = 3, c_2 = 10, n_0 = 1$, by definition $f(n) = \Theta(n^2)$.

#### Problem 2: Iterative Step Counting Analysis
Analyze the time complexity of the following code snippet using line-by-line step counting:

```python
def compute_sum(n):
    total = 0
    for i in range(n):
        for j in range(i):
            total += 1
    return total
```

**Solution:**
* `total = 0`: Executed $1$ time.
* Outer loop `for i in range(n)`: Executed $n + 1$ times (including terminal test).
* Inner loop `for j in range(i)`: Executed $\sum_{i=0}^{n-1} (i + 1) = \frac{n(n+1)}{2}$ times.
* Inner body `total += 1`: Executed $\sum_{i=0}^{n-1} i = \frac{n(n-1)}{2}$ times.
* `return total`: Executed $1$ time.

Total operations $T(n)$:
$$T(n) = 1 + (n+1) + \frac{n(n+1)}{2} + \frac{n(n-1)}{2} + 1 = n^2 + n + 3 = \Theta(n^2)$$

#### Problem 3: Solving Recurrence via Recursion Tree Method
Solve the recurrence relation $T(n) = 2T(n/2) + n$ assuming $T(1) = 1$ using the **Recursion Tree Method**.

**Solution:**

1. **Tree Expansion:**
   * Level 0 (Root): Work = $n$, Subproblems = 1 of size $n$.
   * Level 1: $2$ nodes of size $n/2$. Work = $2 \times (n/2) = n$.
   * Level 2: $4$ nodes of size $n/4$. Work = $4 \times (n/4) = n$.
   * Level $i$: $2^i$ nodes of size $n/2^i$. Work = $2^i \times (n/2^i) = n$.

2. **Height of Tree:**
   The process stops when $n/2^k = 1 \implies 2^k = n \implies k = \log_2 n$.
   Tree height = $\log_2 n$.

3. **Summing Total Work Across All Levels:**
   $$\text{Total Work} = \sum_{i=0}^{\log_2 n} (\text{Work at Level } i) = \sum_{i=0}^{\log_2 n} n = n \times (\log_2 n + 1) = n \log_2 n + n$$

4. **Asymptotic Result:**
   $$T(n) = \Theta(n \log n)$$
